# 订单获取渠道设计计划

本文专门整理订单系统的“订单从哪里来”。目标是让订单获取从当前的拍卖行随机盲盒，扩展成早期可教学、中期可选择、后期可自动化的完整循环。

## 当前获取方式

当前订单入口很少：

- 任务书奖励少量 `createdelight:unopened_order`。
- Lightman's Currency 拍卖行定时刷新 `createdelight:unopened_order`。
- 玩家右键 `createdelight:unopened_order` 后，按玩家 `order_reputation` 生成正式 `createdelight:order`。
- 订单交付器配方会消耗 1 个 `createdelight:unopened_order`，因此前期订单物品还承担了教学和设备制作入口。

当前方式的优点是简单，但缺点很明显：

- 玩家无法稳定获得订单。
- 玩家无法选择订单方向。
- 自动化成熟后，订单来源仍然偏手动。
- 声望只影响订单内容，没有明显改变订单获取体验。
- 拍卖行刷新完全随机，容易和玩家当前产线错位。

## 获取体系目标

订单获取应分成四个层级：

| 阶段 | 主要来源 | 玩家体验 |
|---|---|---|
| 入门 | 任务书、基础商店 | 知道订单系统怎么用 |
| 前期 | 拍卖行、基础订单板 | 有随机机会，也能稳定买小单 |
| 中期 | 订单公告板、订单草稿、印章 | 能按产线选择方向 |
| 后期 | 常驻合同、自动订单源 | 支持持续供货和自动化 |

核心原则：

- 随机订单收益可以更高，但不应是唯一来源。
- 可选择订单收益可以略低，但应更适合产线规划。
- 稳定合同收益最低，但最适合自动化。
- 声望提升后，玩家应明显感觉“订单来源更高级、更可控”。

## 四个核心设计

订单获取和订单生成应围绕四个核心设计展开：

1. 玩家选择方向，但不直接指定最终货物。

   玩家可以选择顾客种族、订单菜单、需求品类或偏好方向，例如精灵茶会、饮品、甜点、主食、油炸食品等。系统在这些方向内生成具体订单。这样玩家能围绕产线接单，但不会完全把订单变成“点菜式提款机”。

2. 重复同类订单有市场饱和。

   玩家可以长期经营某个擅长品类，但反复交付同一类订单后，该方向收益应逐步降低或刷新出更少高价需求。饱和只降低收益，不禁止继续接单，也不强迫玩家立刻换产线。

3. 高级订单自然变成复合菜单。

   高声望顾客和高收益订单可以要求多个大类组合，例如茶 + 甜点、酒 + 主食、快餐 + 饮品。复杂度来自“菜单组合”和“供货规模”，而不是硬性指定某个冷门具体食物。

4. 选择越精确，收益越低。

   随机订单保留最高收益；只选择顾客或菜单时略降；同时筛选多个品类时继续降低；常驻合同收益最低但最稳定。这样玩家可以用收益换可控性，也可以接受随机性换更高回报。

这四条的目标是让订单系统像市场，而不是像任务清单：玩家能表达经营方向，系统保留需求波动；玩家能专精某些产线，但不会因为专精而完全绕过经济平衡。

## 渠道一：任务书订单

定位：教学入口。

建议：

- 保留当前任务奖励 `createdelight:unopened_order`。
- 订单交付器任务额外给 1-3 个基础订单草稿，避免玩家把唯一订单用于合成交付器后没法测试。
- 后续订单章节可以奖励基础印章，例如饮品菜单印章、甜品菜单印章。
- 任务说明应明确：拍卖行可以买随机订单，后续能通过订单构筑台调整订单方向。

适合给：

- 空白订单
- 基础未开封订单
- 入门菜单印章
- 订单构筑台或请求器的教学材料

## 渠道二：拍卖行随机订单

定位：机会型订单来源。

现有 `Order.addOrderToAuction()` 可以保留，但建议分层刷新：

| 声望等级 | 拍卖行可能出现 |
|---:|---|
| 1 | 普通未开封订单、小单草稿 |
| 2 | 顾客印章、饮品/甜品印章 |
| 3 | 菜单印章、少量催化剂 |
| 4 | 稀有顾客订单、高质量催化剂 |
| 5 | 大宗订单草稿、专业合同碎片 |
| 6 | 稀有合同、高风险高收益订单 |

建议刷新逻辑：

- 每半天刷新少量订单相关商品。
- 商品类型由服务器整体时间和在线玩家最高订单声望共同决定。
- 随机订单保留较高收益倍率。
- 已修饰订单草稿可以出现在拍卖行，但价格明显更高。

拍卖行适合卖“机会”，不适合承担稳定供应。

## 渠道三：订单商会商店

定位：稳定基础入口。

使用 Lightman's Currency 系统商店或独立“订单商会”交易器。

建议售卖：

| 声望等级 | 稳定售卖内容 |
|---:|---|
| 1 | 空白订单、普通未开封订单 |
| 2 | 人类商会印章、精灵茶会印章、饮品菜单印章、甜品菜单印章 |
| 3 | 矮人酒馆印章、怪物餐馆印章、主食菜单印章 |
| 4 | 大宗采购催化剂、优质客户催化剂、重签章 |
| 5 | 常驻合同空白、专业顾客印章 |
| 6 | 高级合同升级材料、高风险催化剂 |

价格原则：

- 空白订单应便宜，保证系统可用。
- 带方向的印章应有成本，避免完全替代随机订单。
- 高收益催化剂应较贵，或需要订单回礼材料。
- 常驻合同应昂贵，是后期投资。

这个渠道解决“玩家想玩订单系统却买不到订单”的问题。

## 渠道四：订单公告板

定位：中期主动选择订单。

订单公告板每天生成一组可见订单，玩家可以选择领取。

推荐行为：

- 每天刷新 3-5 个候选订单。
- 显示顾客、订单类型、需求大类、规模、最低质量、基础收益倾向。
- 玩家点击领取后获得正式 `createdelight:order`。
- 已领取的订单从公告板移除，下一天刷新。
- 声望越高，候选池越高级。
- 可以花钱手动刷新，但刷新价格递增。

公告板和拍卖行区别：

- 拍卖行卖盲盒和稀有机会。
- 公告板给玩家看见订单后再选择。
- 公告板订单收益略低于同级随机订单，因为它提供了确定性。

实现建议：

- 第一版可用 MBD2 或 KubeJS GUI 简化实现。
- 数据可存在服务器 persistentData，按世界日刷新。
- 如果 UI 成本太高，第一版可以做成“右键公告板打开聊天列表，点击文本领取”。

## 渠道五：订单草稿与印章

定位：让玩家自己构筑订单。

这个渠道与 `docs/plan/order-acquisition-crystal-modifier-plan.md` 配套。

流程：

1. 玩家获得空白订单。
2. 玩家在订单构筑台放入印章。
3. 草稿获得顾客或菜单倾向。
4. 玩家右键开封，生成更符合预期的正式订单。

优点：

- 玩家能围绕产线接单。
- 不需要公告板每天随机合适订单。
- 可控性可以通过印章成本和收益折扣平衡。

建议：

- 基础印章可重复稳定购买。
- 稀有印章来自拍卖行或订单回礼。
- 一个草稿最多 1 个顾客印章和 1 个菜单印章。
- 开封后订单记录修饰来源，方便奖励倍率调整。

## 渠道六：订单回礼再生产

定位：让完成订单反过来产出更多订单机会。

完成订单后除了钱和声望，可以低概率给：

- 空白订单
- 顾客印章碎片
- 菜单印章
- 催化剂
- 重签章
- 合同碎片

这样玩家完成订单后，不只是拿钱，还会获得“下一轮订单构筑材料”。

建议按顾客主题回礼：

| 顾客类型 | 回礼方向 |
|---|---|
| 人类 | 人类商会印章、快餐/咖啡/面包方向材料 |
| 精灵 | 精灵茶会印章、茶/果汁/甜品方向材料 |
| 矮人 | 矮人酒馆印章、酒/宴席/面包方向材料 |
| 怪物 | 怪物餐馆印章、肉类/烧烤/实验餐方向材料 |

这个渠道能让订单系统形成自循环。

## 渠道七：常驻合同

定位：后期自动化订单来源。

常驻合同不是一次性订单，而是一个长期订单模板。

推荐行为：

- 合同放入机器后，周期性生成订单。
- 合同决定顾客或菜单方向。
- 每次订单的数量和质量仍会波动。
- 生成订单需要手续费或消耗空白订单。
- 合同收益低于随机订单，但稳定。

合同示例：

| 合同 | 生成倾向 |
|---|---|
| 人类茶馆供货合同 | 茶、咖啡、甜点 |
| 快餐连锁供货合同 | 汉堡、炸物、三明治 |
| 矮人酒馆供货合同 | 酒、面包、宴席 |
| 精灵甜品供货合同 | 果汁、蛋糕、冰淇淋 |
| 怪物烧烤合同 | 肉类、烧烤、怪物食品 |

限制建议：

- 声望 4 后解锁普通合同。
- 声望 5 后解锁专业合同。
- 声望 6 后解锁高级合同。
- 同时激活合同数量由声望限制，例如 1/1/2/2/3/4。

这个渠道是订单自动化的终点：玩家不再等订单，而是建设供货线。

## 渠道八：探索与结构战利品

定位：让订单系统和冒险轻度连接。

建议少量加入：

- 村庄、餐馆、商队、市场类结构：空白订单和基础印章。
- 地牢或强盗结构：拍卖凭证、重签章、风险催化剂。
- 精灵/自然主题结构：精灵印章、果汁/甜品印章。
- 矿山/矮人主题结构：矮人印章、宴席/酒馆合同碎片。

注意：

- 探索不应成为订单唯一入口。
- 结构战利品适合给稀有构筑材料，而不是大量正式订单。

## 推荐落地顺序

### 当前分支范围

`feat/order-draft-seals` 已经落地订单获取体系的基础闭环：

- 订单生成参数化：`Order.create(player, spec)` 已支持顾客、菜单、品类、数量、质量和收益倾向。
- 订单草稿与基础印章：`createdelight:unopened_order` 可以写入 `OrderDraft` NBT；基础印章使用一个 `createdelight:order_seal` 物品，通过 `OrderSeal` NBT 区分方向。
- 稳定入口：LC 订单商会商店已经出售未开封订单和基础印章；入门任务额外奖励未开封订单、饮品印章和甜品印章；拍卖行每半天刷新 1-3 个随机订单。
- 订单构筑台：已使用 MBD2 `createdelight:order_builder` 作为事件脚本载体。玩家可用草稿和印章右键构筑台写入方向，也可在构筑台上直接开封草稿。
- 市场饱和：已按玩家记录近期完成的顾客和品类，后续同方向订单交付时会轻微软降金币收益，并随游戏日衰减。

仍未处理：

- 公告板每日候选订单。
- 催化剂、不稳定度、重签章。
- 常驻合同。
- 更完整的订单构筑台 UI 和预览。

当前分支的重点已经从“能否筛选订单”转为“筛选成本、市场反馈和后期自动化来源是否足够清晰”。

### 第一阶段：补齐稳定入口

- 已完成：保留拍卖行随机订单。
- 已完成：LC 订单商会商店出售基础未开封订单和 8 种基础印章。
- 已完成：入门任务额外给 3 个未开封订单，并给饮品、甜品印章。
- 已完成：拍卖行刷新调整为每半天 1-3 个订单。

### 第二阶段：加入可选方向

- 已完成：新增基础顾客印章和菜单印章。
- 已完成：扩展 `Order.create(player, spec)`。
- 已完成：未开封订单读取 `OrderDraft` NBT，根据印章修改生成权重。
- 已完成：LC 订单商会商店出售基础印章。后续可以再按声望拆分货架。

### 第三阶段：公告板

- 做订单公告板。
- 每天生成可见订单列表。
- 支持花钱刷新。
- 订单收益略低于随机订单。

### 第四阶段：订单构筑

- 已完成第一版：MBD2 订单构筑台支持草稿 + 印章。
- 下一步：给构筑台增加更明确的 UI、预览和反馈。
- 下一步：加入重签章和基础催化剂。
- 下一步：拍卖行开始卖稀有构筑材料。

### 第五阶段：常驻合同

- 新增合同道具。
- 合同机器周期性生成订单。
- 与订单请求器和交付器形成后期自动化闭环。

## 推荐最终结构

最终订单获取应呈现这样的分工：

- 任务书：教玩家玩订单。
- LC 商店：保证基础订单不断供。
- 拍卖行：提供随机机会和稀有材料。
- 公告板：让玩家主动挑单。
- 构筑台：让玩家定制订单倾向。
- 回礼：让完成订单产出下一轮订单资源。
- 常驻合同：服务后期自动化。

这样订单系统就不会只是“随机买订单”，而会变成一个有成长、有投资、有自动化终点的经济循环。
## 解析器与订单获取信息透明度

订单获取不只需要“给玩家更多订单”，也需要让玩家理解每个订单入口大概会通向什么结果。当前 CDC 订单解析器已经用于显示草稿、印章和正式订单摘要，因此订单获取渠道应把解析器当作配套信息入口：

- LC 商店或任务奖励给出的基础印章，可以放入解析器查看其覆盖的顾客池或品类池。
- 拍卖行、公告板、回礼和探索战利品给出的稀有构筑材料，后续也应在解析器里显示其影响，而不是只依赖 tooltip。
- 正式订单可放入解析器查看合并后的需求品类摘要，帮助玩家决定是否值得交给请求器自动发货。

这能减少“主食、宴席、饮品”等抽象词造成的不确定感，也能避免玩家为了理解订单生成规则去查数据文件。
