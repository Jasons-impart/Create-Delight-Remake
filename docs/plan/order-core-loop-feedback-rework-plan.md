# 订单核心循环反馈精简计划

状态：已按 2026-08-17 的减法决策实施；当前权威设计见 `docs/order-system-design.md`。

## 参考结论

Vault Hunters 的核心优势不是系统多，而是每次进入宝库都有清晰目标、可读选择、即时战利品和长期成长。订单系统对应的核心应是：先看见值得做的候选，再决定扩哪条产线，履约后立即得到金币、声望、凭证、回礼或下一单条款。

## 保留的闭环

`公告板选单 -> 草稿定向 -> 开封 -> 仓库备货 -> 交付 -> 奖励 -> 补缺或扩产`

- 公告板用适配、拓展、机会三选一降低盲抽。
- 小类定向代替固定物品 ID，保留产线内部选择。
- 适配单的全部条目都必须来自公告板列出的小类。
- 普通订单和加急订单只衰减额外金币，不硬失败。
- 市场饱和削弱长期重复方向，机会单提供可见换线诱因。
- 每单保留 LC 商会凭证，使订单奖励能回流到供货补缺。

## 删除清单

- 订单解析器的新获取路线。
- 订单构筑台的新获取与完整功能。
- 普通重签章与拍卖行重签材料。
- 薄利多销、特急救场的新产出；旧物分别映射到大宗采购和加急配送。
- 反季采购的新产出，仅保留旧订单兼容。
- 供货样品登记、个人永久目录、四种顾客关系。
- 七日运力、超额倍率、供应压力。
- 自动目标、安全水位、预存预算和供货双页 UI。
- 复制订单、合同调度与自动签发路线。

## 供货边界

供货委托以首次获得目录物品作为永久解锁条件，支付商会凭证与 LC 钱包金币，并按固定批量、固定工期生成延迟地址包裹。

## 迁移

- 旧样品槽只允许取回。
- 旧预存预算在原所有者打开委托台时退回。
- 旧活动委托继续到货。
- 旧构筑台保留注册和库存界面，但功能退役。
