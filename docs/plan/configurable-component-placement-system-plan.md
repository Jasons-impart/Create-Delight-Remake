# 标准组件构形模块系统设计

本文记录一种基于现有标准组件的可切换放置系统。玩家手持构形模块时，可以按住 `Ctrl` 并滚动鼠标滚轮切换放置形态；右键后放置对应的真实方块，并按形态消耗构形量或额外特征零件。

本文仅记录前瞻设计。物品名称、构形量数值、模式池、配方和实现类均可在原型测试后调整，不代表相关物品已经注册或进入生存流程。

## 设计结论

- 系统名称暂定为“构形模块”；物品显示名可以继续使用“混沌物·传动”等更有世界观色彩的名称。
- 第一版只实现传动构形模块，并只开放转轴、小齿轮和大齿轮三种无方块实体形态。
- 模块本体为不可堆叠的可充填工具，标准组件负责补充构形量；不制作需要长期占用多个物品栏的一次性构形物堆栈。
- 普通基础方块只消耗构形量；高价值方块额外消耗机壳、电子管、齿轮或其他特征零件。
- 机器不能只靠通用构形量生成。未来的机器施工模块必须继续消耗现有标准组件组合和机器特征零件。
- 放置后生成原模组的真实方块，挖掘时遵循原方块掉落；方块不能直接还原成构形量，避免无损跨物品转换。
- 原版和模组原有配方全部保留。构形模块提供便携施工和临场选择，直接批量合成仍应拥有更高材料效率。

## 设计目标

- 减少大型工厂建设时转轴、齿轮、管道、机壳和控制元件对快捷栏与背包空间的占用。
- 让玩家通过一个稳定的输入方式快速切换同类方块，减少打开背包和 JEI 的频率。
- 让现有安山结构、传动、铜质流体、密封接头、黄铜控制和逻辑组件获得持续使用场景。
- 保留机械动力中不同结构、传动、流体和机器零件的成本差异。
- 让直接合成、自动化量产和构形模块分别承担“材料效率”“批量生产”和“现场施工便利”三种职责。
- 使用显式白名单和数据驱动模式表扩展附属模组，不自动把整个物品标签转化为可放置内容。

## 非目标

- 不制作一份材料可以免费变成任意机器的万能物品。
- 不允许转轴、大齿轮、齿轮箱和机器在拆除后无损互相转换。
- 不用构形模块替代原有配方、任务教学、自动化产线或仓储物流。
- 不在第一版处理传送带、轨道、软管滑轮、动力结构、成对放置方块或复杂方块实体。
- 不在第一版支持携带机器库存、流体、过滤器、频率、红石配置或其他方块实体 NBT。
- 不通过客户端单方面修改物品模式、构形量或消耗结果。

## 与现有标准组件的关系

现有组件已经形成可直接复用的职责划分：

| 标准组件 | 当前职责 | 构形系统用途 |
|---|---|---|
| `createdelight:andesite_structure_component` | 基础框架和安山机器主体 | 结构构形模块、机器主体成本 |
| `createdelight:kinetic_transmission_component` | 旋转与运动机构 | 传动构形模块充填、基础机器传动成本 |
| `createdelight:copper_fluid_component` | 铜质流体设备主体 | 流体构形模块主体与充填 |
| `createdelight:sealed_joint_component` | 密封、活动接口和流体连接 | 流体模块外壳、高级流体形态成本 |
| `createdelight:brass_control_component` | 黄铜精密控制 | 控制构形模块和精密机器成本 |
| `createdelight:logic_component` | 打包、库存与物流网络 | 物流构形模块和网络设备成本 |

构形系统不建立新的平行材料等级。标准组件决定模块属于哪个工程领域，特征零件继续决定具体方块或机器的身份。

## 玩家操作循环

1. 玩家完成对应工程阶段，制作某一类构形模块。
2. 玩家使用标准组件为模块补充构形量。
3. 手持模块时，按住 `Ctrl` 并滚动鼠标滚轮切换当前模式。
4. 屏幕提示和物品提示显示当前形态、构形量、单次消耗与额外材料。
5. 玩家右键方块表面，模块按照目标方块原本的放置规则确定朝向和位置。
6. 放置成功后由服务端扣除构形量与额外材料；放置失败时不消耗。
7. 放下的目标是原模组真实方块，后续连接、旋转、应力、流体和挖掘行为保持原样。

## 输入与界面

### 默认操作

- `Ctrl + 向上滚轮`：切换到上一个形态。
- `Ctrl + 向下滚轮`：切换到下一个形态。
- 仅当主手物品为构形模块时取消原快捷栏滚动。
- 控制键必须注册为可配置按键或修饰键，避免与玩家现有键位冲突。
- 服务端保存最终模式；客户端只负责捕获输入、发送请求和显示即时预览。

### 显示信息

物品提示至少显示：

- 当前模式及目标物品 ID。
- 当前构形量和最大构形量。
- 放置一次需要的构形量。
- 额外消耗的机壳、电子管、齿轮或其他特征零件。
- `Ctrl + 滚轮切换形态` 的操作说明。

建议在准星附近短暂显示目标物品图标和名称。第一版不制作径向菜单；当单个模块超过八种模式后，再评估长按按键打开径向菜单。

## 构形量模型

### 基本规则

- 每个模块最大构形量暂定为 `64`。
- 模块不可堆叠，物品耐久条位置显示剩余构形量比例。
- 创建模块时自带一次对应组件的充填量。
- 补充配方必须保留模块的模式、构形量与数据版本。
- 构形量到达上限后不能继续补充；配方不得静默吞掉溢出部分。
- 创造模式不消耗构形量或额外材料，但仍由服务端验证模式和放置结果。

### 便利溢价

构形模块不能比直接配方便宜。设计目标为：

- 批量制造某一种固定方块时，直接配方或自动化产线最省材料。
- 临时需要多种同类方块时，构形模块用额外成本换取快捷栏空间和选择自由。
- 初始数值按约 `20%` 至 `50%` 的便利溢价设计，之后根据生存测试调整。

传动组件当前由转轴、齿轮、安山合金和铁锭合成，每次产出两个。第一版采用“一枚传动组件补充四点传动构形量”的保守换算，避免构形模块反过来成为更高效的转轴或齿轮生产配方。

## 模块配方草案

构形模块本体优先使用锻造台制作，与现有“组件作为模板、主体作为基础、特征零件作为附加”的机器配方语言保持一致。

| 模块 | 模板槽 | 基础槽 | 附加槽 | 初始构形量 | 推荐解锁 |
|---|---|---|---|---:|---|
| 传动构形模块 | 传动组件 | 安山机壳 | 电子管 | 4 | 安山时代后期 |
| 结构构形模块 | 安山结构组件 | 安山机壳 | 强力胶 | 4 | 安山时代后期 |
| 流体构形模块 | 铜质流体组件 | 铜机壳 | 密封接头组件 | 8 | 完成基础流体教学后 |
| 控制构形模块 | 黄铜控制组件 | 黄铜机壳 | 精密构件 | 4 | 黄铜与精密构件阶段 |
| 物流构形模块 | 逻辑组件 | 黄铜机壳 | `create:transmitter` | 4 | 打包与库存网络阶段 |

显示名可以使用：

- `混沌物·传动`
- `混沌物·结构`
- `混沌物·流体`
- `混沌物·控制`
- `混沌物·物流`

内部注册名建议保持工程语义，例如：

- `createdelight:kinetic_configuration_module`
- `createdelight:structural_configuration_module`
- `createdelight:fluid_configuration_module`
- `createdelight:control_configuration_module`
- `createdelight:logistics_configuration_module`

### 充填配方

| 模块 | 充填材料 | 补充量 |
|---|---|---:|
| 传动构形模块 | 传动组件 ×1 | 4 |
| 结构构形模块 | 安山结构组件 ×1 | 4 |
| 流体构形模块 | 铜质流体组件 ×1＋密封接头组件 ×1 | 8 |
| 控制构形模块 | 黄铜控制组件 ×1 | 4 |
| 物流构形模块 | 逻辑组件 ×1 | 4 |

充填需要自定义配方逻辑，不能使用会丢失或复制 NBT 的普通静态产物配方。第一版只要求手动充填；Create 部署器或其他自动充填应在自定义配方能够可靠复制模块 NBT 后再接入。

## 第一版：传动构形模块

### 模式池

第一版只开放三个基础形态：

| 模式 | 目标方块 | 构形量消耗 | 说明 |
|---|---|---:|---|
| 转轴 | `create:shaft` | 1 | 最低成本的基础传动件 |
| 小齿轮 | `create:cogwheel` | 2 | 包含木材形态成本和现场选择溢价 |
| 大齿轮 | `create:large_cogwheel` | 3 | 用于变速，保留高于小齿轮的成本 |

一枚传动组件补充四点后，玩家可以选择放置四根转轴、两个小齿轮，或一个大齿轮并保留一点构形量。直接批量合成固定方块仍然更高效。

### 第一版暂不加入

| 方块 | 暂缓原因 |
|---|---|
| `create:gearbox` | 原配方包含安山机壳和四个齿轮，需要先实现额外特征材料消耗 |
| `create:encased_chain_drive` | 原配方主要由安山机壳和铁粒组成，不适合只消耗传动构形量 |
| `create:clutch` | 原配方包含安山机壳和红石，应进入带额外材料检查的扩展版本 |
| `create:gearshift` | 原配方包含安山机壳、齿轮和红石，应进入控制扩展版本 |
| `create:adjustable_chain_gearshift` | 需要链式传动箱和电子管，阶段与成本均高于基础传动件 |
| 传送带 | 两点选取、长度消耗和连接状态不适合第一版通用 `BlockItem` 放置流程 |

### 传动扩展版本

在额外材料消耗机制验证后，可以加入：

| 模式 | 构形量 | 额外材料 |
|---|---:|---|
| 齿轮箱 | 8 | 安山机壳 ×1 |
| 链式传动箱 | 2 | 安山机壳 ×1、铁粒 ×3 |
| 离合器 | 1 | 安山机壳 ×1、红石粉 ×1 |
| 反转齿轮箱 | 2 | 安山机壳 ×1、红石粉 ×1 |
| 可调链式传动箱 | 2 | 链式传动箱 ×1、电子管 ×1 |

扩展模式的额外材料以原配方的特征部分为基准；构形量只替代该工程领域中的通用基础部分。

## 后续模块模式草案

### 结构构形模块

候选内容为安山机壳、底盘和不带方块实体的结构件。不同底盘的粘连、朝向和范围设置需要单独测试，不能仅凭注册表类型自动加入。

### 流体构形模块

| 模式 | 构形量 | 额外材料 |
|---|---:|---|
| 流体管道 | 1 | 无 |
| 玻璃流体管道 | 1 | 玻璃 ×1 |
| 流体阀门 | 1 | 铁板 ×1 |
| 动力泵 | 1 | 小齿轮 ×1 |
| 智能流体管道 | 1 | 黄铜板 ×1、电子管 ×1 |

流体管道的连接状态由原方块放置和邻居更新逻辑决定。智能管道等黄铜内容即使出现在模式表中，也必须由模块等级或升级状态限制。

### 控制构形模块

控制模块用于红石控制、精密传动和序列控制件。它是便利工具的阶段升级，不影响玩家通过原配方更早制作离合器或反转齿轮箱。

### 物流构形模块

物流模块用于打包、库存和请求网络的现场施工。漏斗、溜槽等简单方块可以只消耗构形量；库存连接器、请求器、打包机和交易网络设备必须保留发信器、纸板、库存连接器或容器等特征材料。

## 机器施工模块边界

机器类不能沿用“只扣一个通用数值”的模式。未来若加入机器施工模块，应遵守以下规则：

- 模块本体只负责选择目标机器和执行放置。
- 放置时直接从玩家背包消耗对应标准组件组合和特征零件。
- 基础机器继续使用“安山结构组件＋传动组件＋特征零件”。
- 流体设备继续使用“铜质流体组件＋密封接头组件＋特征零件”。
- 精密机器继续使用黄铜控制组件、安山结构或传动组件和精密构件。
- 物流机器继续使用逻辑组件、安山结构或黄铜控制组件和对应特征零件。
- 现场施工每次只放置一台机器。即使原锻造台或序列装配配方一次产出两台，施工模式也不获得双倍产量；额外成本是现场选择和免工作台组装的便利溢价。
- 第一版机器白名单只能包含空状态机器，不能复制或迁移库存、流体、过滤器、频率、配方卡或所有者数据。

因此机器施工模块是后期施工工具，不是新的机器量产路线。玩家要批量生产机器时，仍应使用现有锻造台和序列装配配方。

## 数据与实现边界

### 推荐归属

按键监听、网络包、自定义物品、动态 NBT 充填和服务端放置验证需要 Java 实现，推荐归属 Create Delight Core。KubeJS 负责整合包配方、任务书、语言和数据白名单，不承担核心输入与同步逻辑。

### 模块物品数据

建议保存以下字段：

```text
Mode: 当前模式 ID
Charge: 当前构形量
Tier: 模块等级或升级状态
DataVersion: 数据版本
```

模式使用稳定字符串 ID，不使用列表下标作为持久化值。调整模式排序时，旧物品仍能解析到原模式；模式被移除时回退到该模块的第一个有效模式。

### 数据驱动模式表

每个模式至少声明：

```text
module: 所属模块
mode: 稳定模式 ID
target: 目标物品或方块 ID
chargeCost: 构形量消耗
extraIngredients: 额外材料列表
requiredTier: 所需模块等级
placementPolicy: 放置策略
```

模式表必须使用显式条目，不直接读取大范围物品标签。第三方模组更新或配置禁用目标方块时，该模式应在数据加载阶段被过滤并给出明确日志。

### 放置流程

1. 客户端捕获 `Ctrl + 滚轮`，只发送模式切换方向或目标模式 ID。
2. 服务端确认玩家主手仍为对应模块，验证目标模式属于允许列表，再更新物品 NBT。
3. 右键时服务端预检查构形量、额外材料、目标位置、玩家权限和方块是否可放置。
4. 使用目标 `BlockItem` 原有的放置逻辑处理方向、水含状态和邻居关系。
5. 仅在放置返回成功后扣除构形量与额外材料。
6. 客户端从服务端同步后的物品栈和世界状态刷新预览。

第一版只支持普通 `BlockItem`。拥有多阶段交互、特殊 `useOn`、成对放置、长度计算或方块实体初始化逻辑的目标，需要专用放置策略后才能加入。

## 防套利与兼容规则

- 构形模块不能作为普通配方中的任意目标方块替代品。
- 放置方块掉落其自身，不返还构形量；构形量只能由规定的标准组件充填。
- 不提供目标方块到构形量的无损逆向配方。
- 如果未来提供拆解回收，回收效率必须低于直接制造，并按目标方块的原材料族返回组件或残片。
- 额外材料必须由服务端原子检查；材料不足时不得先放置后回滚。
- 切换模式不改变构形量，也不允许通过 NBT 合并、铁砧、磨石或修复配方复制充填量。
- 模块不允许进入机械动力动态结构库存后自动放置，除非后续为部署器和蓝图炮建立明确兼容规则。
- 模式白名单只加入已针对当前安装版本验证的方块；相同标签或相似名称不是兼容证据。

## 解锁阶段

| 阶段 | 开放内容 | 设计目的 |
|---|---|---|
| 安山时代前半 | 原有转轴、齿轮和机壳配方 | 让玩家学习应力传递、齿轮变速和基础放置 |
| 安山时代后半 | 传动构形模块第一版、结构构形模块 | 开始建设成规模工厂时减少快捷栏负担 |
| 铜质流体教学后 | 流体构形模块 | 玩家已经理解管道、泵和流体方向后提供施工便利 |
| 黄铜与精密构件阶段 | 控制模块、传动高级模式 | 让模式切换与精密控制形成阶段升级 |
| 打包与库存网络阶段 | 物流构形模块 | 服务中心仓库和大型物流网络建设 |
| 中后期大型工厂 | 机器施工模块候选 | 方便复制成熟产线，但保留标准组件和特征零件消耗 |
| 终局候选 | 多模块统一构形核心 | 仅合并操作入口，不合并不同组件的成本账户 |

构形模块属于便利解锁，不应成为原方块的硬门槛。玩家在获得模块前仍能通过原配方制作全部对应方块。

## 实施阶段

### 第一阶段：传动原型

- 注册传动构形模块。
- 实现 `Ctrl + 滚轮` 模式切换和服务端同步。
- 实现转轴、小齿轮和大齿轮三种模式。
- 实现四点一批的传动组件充填配方。
- 实现物品提示、构形量条和短暂模式切换提示。
- 只验证普通手持放置，不接入部署器、蓝图炮或动态结构。

### 第二阶段：特征材料

- 为模式加入额外材料要求。
- 加入齿轮箱、离合器、反转齿轮箱和链式传动件。
- 验证材料检查、放置成功和消耗的原子性。

### 第三阶段：结构与流体

- 加入结构和流体构形模块。
- 验证管道连接、水含状态、泵朝向和黄铜模式阶段锁。
- 将第一批模块加入“机动机器标准组件”之后的任务书说明。

### 第四阶段：控制与物流

- 加入精密传动、控制和物流模式。
- 对配置可禁用或依赖附属模组的目标做数据加载过滤。
- 评估模式数超过八个后的径向菜单。

### 第五阶段：机器施工候选

- 只选择少量无初始 NBT 的基础机器验证。
- 放置时消耗精确标准组件组合和特征零件。
- 与现有锻造台、序列装配产量比较，确保施工模式始终存在便利溢价。

## 第一版验收标准

- 手持模块时 `Ctrl + 滚轮` 能稳定循环三个模式，快捷栏选中槽不会变化。
- 客户端连续快速滚动后，服务端模式、客户端提示和实际放置结果一致。
- 放置转轴、小齿轮和大齿轮时沿用原方块的朝向与放置限制。
- 构形量不足、目标位置无效或玩家无权限时不放置、不扣费。
- 生存模式成功放置后只扣除规定构形量；创造模式不扣费。
- 充填配方保留模式和数据版本，不允许复制构形量或吞掉溢出组件。
- 放置后的方块参与原 Create 应力网络，挖掘时掉落原方块。
- 原转轴、齿轮和标准组件配方不被移除或替换。
- JEI、任务书和中英文提示明确说明模块是便利施工工具，而不是更高效的生产路线。
- 静态代码、数据和构建验证不等同于游戏内验证；完成客户端重启后的放置、联机同步和应力网络回归后，才能标记运行时通过。

## 待原型确认的问题

- “混沌物”是否作为正式显示名，还是仅保留给终局统一模块。
- 模块图标是固定外壳叠加当前模式角标，还是直接显示当前目标方块图标。
- 充填是否只使用自定义合成配方，还是增加工作台、部署器或专用充填设备。
- 第一版最大构形量采用 `32` 还是 `64`；默认采用 `64`，避免大型工厂频繁补充。
- 服务器是否允许配置禁用部分模式或修改构形量成本。
- 终局统一模块是否有足够价值；如果分类模块已经易于携带，则不必强行合并。
