# Tetra 五章模块图鉴重建方案

## 实施结论

Tetra 任务组保留组 ID `57E934AC8166BC73`，由旧的分散章节重建为五章：

| 顺序 | 章节 | 文件 | 性质 |
|---:|---|---|---|
| 0 | 基础工艺 | `Those_Who_Came_Before.snbt` | 操作教学、检测任务与奖励 |
| 1 | 近战武器与工具 | `Tetra_Weapons.snbt` | 查询型图鉴 |
| 2 | 远程、防御与携行 | `Tetra_Ranged_Defense.snbt` | 查询型图鉴 |
| 3 | 护甲与饰品 | `Tetra_Armor_Curios.snbt` | 查询型图鉴 |
| 4 | 卷轴与锻造技艺 | `Tetra_Scrolls.snbt` | 查询型图鉴 |

所有章节、任务、任务项和基础章奖励均使用新 ID，旧玩家的 Tetra 任务进度不会继承。介绍页进入基础工艺的 `change_page` 同步指向新章节 ID。

## 玩家查询结构

基础工艺继续承担加工台、全息球、工具架、模块化物品、锻造遗迹、锤级和打磨等操作教学。高级锤材料不再在基础章展开，七级锤页面只提供前往“双头工具 → 工具头 → 锤头”的跳转。

其余四章统一使用查询树：

```text
章节根 → 物品家族 → 槽位 → 命名模块 → 专属改进
```

- 近战章覆盖模块化剑、单头工具、双头工具和当前可用的 MMT 法杖。
- 远程章分别展示 Tetra 弓、MMT 弓、弩、盾牌和工具腰带；完整模块 ID 不同的同名模块不合并。
- 护甲饰品章左侧为四部位模块化护甲，右侧为戒指、手镯、项链、手套、鞋、护心镜、徽章、王冠、不死图腾、护符和纯白四系。
- 卷轴章逐张展示需要单独查询的可获取卷轴；镀金 I–V 合并为一页，泰坦内容按四条“三卷轴 → 三火种汇卷”路线汇入真我之诗，十二首当前可用颂歌只在真我之诗正文中分组列名。

纯白容器、剑鞘、箭袋和书袋分别保留白色核心及七种颜色模块。为了避免四组各出现七个只有一个叶子的空泛槽位，七种颜色在每件物品下共用一个“七种色彩模块”槽位节点，七个命名模块仍全部独立成页。

## 有效数据边界

生成器以当前安装内容为准，模块必须同时满足：

1. 当前资源层中存在有效模块定义；
2. 具有可用的加工台 schematic；只存在于 replacement 或默认物品栈中的固有模块不建页；
3. 模块 `type`、`slots` 和 `variants` 有效；
4. 所需模组已经安装；生成器只读取 `mods.toml` 的 `[[mods]]` 实际声明，不把 `[[dependencies.*]]` 中的可选依赖误判为已安装内容；
5. 没有出现在本次运行日志的模块或 schematic 加载失败列表中。

当前明确排除：

- `greatsword/more_mod_tetra/mmt_odachi` 残留；
- 未安装 Goety 的暗魔杖、戒指、王冠、徽章等联动；
- 未安装 Malum、Eidolon、Botania 等依赖的模块和卷轴；
- 已禁用的稳固 I/II、超凡铭刻、通用技能、暴击技艺和升级下界合金卷轴；
- 昔涟、开拓等已禁用颂歌；
- 没有有效数据或获取途径的“尖端”。

当前生成清单及具体排除原因见 `docs/plan/tetra-compendium-generation-report.md`。

## 图标生成

`scripts/generate-tetra-compendium.py` 负责确定性生成四个图鉴章，并重置基础章 ID。

模块化物品图标遵循以下规则：

- 从物品的默认 replacement 与安全回退模板补齐必需槽位；
- 以模块定义中的真实 `slots` 写入目标模块；
- 多槽模块按 `slotSuffixes` 写入左右或多个实际槽位；
- 从模块允许的材料分类中选取当前有效材料，并写入 `{module}_material`；
- MMT 饰品不使用 replacement 中的 `relic/casing` 别名作为最终 NBT 槽位，而使用成品类实际读取的 `mmt_*` 槽位；
- 卷轴图标复制真实 `BlockEntityTag.data`，包含 key、schematics、material、ribbon 和 glyphs；运行时生成的效率专著和材料专长使用其真实键、材质和缎带，并固定一个有效图案。

## 排布与文案

- 章节根位于 `(0, 0)`，尺寸 `3.0`。
- 物品根尺寸 `2.5`，槽位尺寸 `2.0`，模块与卷轴尺寸 `1.75`。
- 叶节点使用二至四列紧凑网格，纵向间距约 `2.0`。
- 每章 `autofocus_id` 指向章节根。
- 护甲饰品章从中央分别向左右展开，避免把两个大系统串成一条长线。
- 物品、槽位和关键升级关系保留必要依赖线；普通“槽位 → 模块”归属线隐藏，避免数百条线路覆盖页面。依赖要求为 `all_started`，详情始终可打开并隐藏锁图标。
- 图鉴只使用复选阅读任务，不设置奖励。
- 正文一行一个字符串，优先使用 `&e用途：`、`&b适合：`、`&d需要：` 和 `&a改进：`。
- 模块名、模块说明和槽位名优先读取 `kubejs/assets/*/lang/zh_cn.json`，其次读取当前安装 JAR 的语言键，只有语言键缺失或为空时才使用中文回退；不根据内部槽位名自行创造“血槽”等术语。
- 卷轴正文读取游戏 tooltip 在“原理图”标题下使用的 `item.tetra.scroll.<key>.description`，同样按 KubeJS → 当前安装 JAR 的优先级解析；保留原颜色与完整语义，并按换行、句末和长逗号句拆成短行，不使用统一的解锁模板。
- 不创建没有具体子页或独立机制内容的空泛汇总叶节点；“通用剑刃改进与打磨”已移除，实际模块、双剑阶段和高级锤材料仍直接挂在对应分支。
- 玩家正文不展示已移除内容、模组迁移、未来计划或开发理由。

## 当前规模

当前数据快照收录 230 个可在加工台选择的命名模块，以及 68 张卷轴或锻造技艺页。四个图鉴章共 429 个节点；固有初始模块、空泛汇总叶节点、镀金分级节点和十二首颂歌的重复叶节点已经合并或排除。

详细分布由生成报告记录，模组或数据包更新后应重新运行生成器，不能手工增补零散节点。

## 验证要求

静态验证：

- 全局 16 位 ID 唯一，且处于正 signed-long 范围；
- 五章顺序、组 ID、`autofocus_id`、依赖和 `change_page` 有效；
- 四个图鉴章没有奖励，正文使用短行和颜色字段；
- 每个有效模块恰好生成一个模块页，每个可获取卷轴恰好生成一个卷轴页；
- 图标包含实际模块与材料 NBT，卷轴包含完整 `BlockEntityTag.data`；
- 未安装依赖、失效 schematic、禁用卷轴、旧内容和 `mmt_odachi` 不进入玩家任务。

实机验证：

- 已执行 `/ftbquests reload`，运行日志确认载入 40 个章节和 2495 个任务且没有新增任务解析错误；
- 在常用 GUI 缩放下检查根节点 autofocus、图标尺寸和叶节点密度；
- 抽查每种物品家族的目标模块图标；
- 逐类检查效率、材料、饰品、法杖、泰坦、汇卷和颂歌图标；
- 验证介绍页、基础工艺高级锤、模块到卷轴、卷轴回模块和泰坦合成链跳转。
