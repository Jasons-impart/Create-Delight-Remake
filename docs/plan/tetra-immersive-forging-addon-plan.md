# Tetra 沉浸式全息锻造附属设计方案

## 1. 文档状态

- 状态：V1 原型已实现；局部离屏纹理与自适应刷新已完成开发环境实机回归，完整 CDR/Shader 矩阵仍待发布前复核。
- 目标平台：Minecraft 1.20.1、Forge 47.4.x、Tetra 6.9.x。
- 建议形态：独立 Tetra 客户端附属；不并入 Tetra Insight，也不把 Tetra 硬依赖加入 Create Delight Core。
- CDR 基线：保留 Tetra、Tetra Insight、ExtraHoloPage 与 Tetra View 的现有功能；本方案只增加世界空间投影、输入映射与加工表现。
- 相关记录：[Tetra Insight 整合与发布记录](tetra-insight-integration.md)。

## 2. 背景与问题

Tetra 的页面在设定上由全息球或工作台投射，但当前体验仍是打开覆盖画面的普通 GUI。玩家看不见投影与设备之间的空间关系，打开和关闭 Screen 也会突然中断对世界的观察。

另一方面，Tetra 页面信息密度很高，若重新制作一套简化世界 UI，容易丢失槽位、分页、Tooltip、材料影响、改进预览和兼容附属功能。因此本方案不重做页面，而是把原页面的最终绘制结果作为真实世界中的投影内容。

普通加工台的模块更换也几乎瞬时完成。悬挂锻造锤已有锤击和维护表现，但常规装配、切削、打磨、固定与更换模块缺少动作、声音和阶段反馈，使全息方案选择与实际加工彼此割裂。

## 3. 设计目标

1. 保留 Tetra 原有 Screen、Menu、页面、选材、预览、改进、打磨、附魔、Tooltip 与确认逻辑，不建立第二套功能不完整的界面。
2. 放置全息球和工作台使用设备锚定的真实世界投影；手持全息球使用相机正前方、随视野移动但仍参与世界深度的四边形，不退回普通二维菜单。
3. 玩家观察投影时仍可正常移动、跳跃、疾跑和转头；只有主动聚焦后才暂时把输入交给原 Tetra Screen。
4. 聚焦期间仍只显示世界投影，不显示普通全屏菜单、不铺设黑色世界遮罩，也不改变玩家朝向。
5. 为普通加工台提供符合实际工具需求的短加工演出，使模块更换不再只是无反馈的物品刷新。
6. V1 保持纯客户端，不改变存档、配方、材料消耗、锤级、制作耗时、数据包时机或成功判定。
7. 以黑、白、灰为投影结构语言，同时保证文字、槽位、物品和材料辨识度。
8. 与 Tetra Insight、ExtraHoloPage 和 Tetra View 保持明确兼容边界。

## 4. 非目标

V1 不包含以下内容：

- 不增加服务端锻造状态机、失败率、节奏判定、耐力或强制等待时间。
- 不拦截、取消、延迟或重发 Tetra 的制作数据包。
- 不复制 `canApplyUpgrade`、材料扣除或 `craft()` 的判定逻辑。
- 不要求玩家按指定节奏实际挥锤，且不因投影关闭、掉线或演出中断而改变制作结果。
- 不重做 Tetra 遗迹、锤级、卷轴、打磨进度与物品平衡。
- 不替代 Tetra View 的独立物品查询职责。
- 不让其他玩家看见本地锻造演出；多人可见动作属于后续双端版本范围。
- 不把经典全屏 GUI 作为普通玩家可切换、可记忆的常驻表现。

## 5. 产品形态与项目边界

独立项目建议使用 `Tetra Immersive Forging`，源码位于 `D:\learnmod\TetraImmersion`，发布后再通过 Packwiz 接入 CDR。

| 组件 | 职责 |
|---|---|
| Tetra | 制作规则、容器、材料消耗、结果物品与服务端权威结算。 |
| Tetra Insight | 信息可发现性、材料换算、筛选分页、改进详情与原页面扩展。 |
| 新附属 | 世界投影、离屏绘制、输入反算、生命周期、台面表现、声音、粒子与本地加工演出。 |
| ExtraHoloPage | 现有扩展布局与材料提示；新附属承载其最终页面，不重新计算内部布局。 |
| Tetra View | 保持原有独立查询入口和按键行为。 |

新附属可以提供很窄的只读兼容接口，用于取得当前页面、选中方案、预览物品和工具需求；不得让兼容附属承担服务端逻辑。

## 6. 核心体验模型

正常流程始终只有一块世界空间投影。`OBSERVING` 与 `FOCUSED` 是同一投影会话的交互状态，不是两种界面呈现。

```text
原 Tetra Screen / Menu
        │  页面状态、槽位、按钮、网络逻辑
        ▼
离屏 Framebuffer / RenderTarget
        │  原页面最终纹理
        ▼
世界空间投影四边形
        ▲
相机或鼠标射线 → 平面 UV → 原 GUI 坐标
```

原 Screen、Menu 和页面状态在整个会话中保持同一实例。观察、聚焦和失焦只能改变输入归属与主画面绘制方式，不能重新打开容器、清空 carried stack、筛选、翻页、选材、悬停预览或已选改进。

## 7. 投影会话状态机

### 7.1 `CLOSED`

- 没有 retained Screen、Menu 引用、离屏目标或世界投影。
- 玩家输入完全按原版处理。

### 7.2 `OBSERVING`

- 打开全息球或工作台后的默认状态。
- 原 Tetra Screen 与 Menu 被保留并继续接收同步，但普通 Screen 不占用玩家输入。
- 世界投影持续绘制，玩家可正常 WASD、跳跃、疾跑、潜行和转头。
- 对放置全息球和工作台，准星射线命中投影内容时，左键、右键和滚轮直接映射为原 Screen 的对应操作；准星本身就是指针，不额外绘制光标。
- 手持全息球固定在视野正前方后，准星相对页面只会停在同一位置，因此完整页面主要通过选取方块键进入鼠标聚焦操作。
- 选取方块键在 `OBSERVING` 与 `FOCUSED` 之间切换；设备锚定投影可在观察态用准星点击拾取、携带并再次点击放置 carried stack，按住拖拽快速分配、文本输入和手持全息球完整页面仍使用鼠标聚焦。
- 操作提示读取玩家当前键位并以紧凑黑白提示显示，不再占用准星附近；放置设备和加工台提示位于左下角，手持投影唯一且关键的鼠标模式提示贴近投影左上侧外缘，避开准星、正文和生存 HUD。提示显示约 `2.5 s` 后用约 `1 s` 淡出，重新命中投影、切换模式或更换提示类型时重新出现。
- 手持投影在 `OBSERVING` 中不接管攻击、使用和滚轮；这些输入继续作用于世界，只有选取方块键进入 `FOCUSED` 后才操作完整页面。
- 除命中投影的交互键及明确关闭键外，不全局吞掉普通移动与视角输入。

### 7.3 `FOCUSED`

- 世界投影仍在原位置持续绘制，不切换为普通菜单。
- retained 原 Tetra Screen 临时成为 `Minecraft.screen`，直接接收其原生鼠标、键盘、字符输入和容器生命周期。
- 主画面渲染期间临时阻止该 Screen 的普通二维绘制；原页面只进入离屏目标并显示在世界四边形上。
- 聚焦期间相机与移动可按普通 Screen 语义暂停，以保证槽位拖拽和文字输入精度；世界本身继续运行。
- `Esc` 只执行失焦：`FOCUSED → OBSERVING`，不得调用 `onClose()`、发送容器关闭包或执行 HoloGui 的关闭回调。
- 选取方块键也可执行同一失焦操作；若原容器仍携带物品或正在拖拽，则拒绝失焦，避免物品成为不可见光标。
- 观察态用 `Esc` 关闭投影时会取消原版 `PauseScreen`；必须在下一客户端 tick 恢复该次 `pauseGame()` 随后暂停的声音通道，不能在 Opening 事件内同步恢复。

### 7.4 `CLOSING`

- 从观察态再次按 `Esc`、按 `E`、主动关闭或收到合法关闭条件时进入。
- 只在此状态调用一次原 Tetra 关闭生命周期。
- 可保留最后一帧纹理播放 120–220 ms 的折叠动画，但逻辑菜单已经关闭且不再接受输入。

### 7.5 `INVALID`

以下情况立即释放输入并清理会话：

- 服务端关闭当前容器或客户端 `containerMenu` 已替换。
- 工作台或放置全息球被破坏、替换或区块卸载。
- 玩家死亡、断线、切换维度或世界卸载。
- 手持全息球来源不再存在于原手或原物品上下文。

短暂遮挡、设备锚定面板因转头离开视野或轻微超出舒适交互距离，不属于经典 GUI 回退条件。聚焦失去有效命中时应先返回观察；来源长期无效或超过原容器有效距离时再关闭。

### 7.6 状态转换

| 事件 | 转换 |
|---|---|
| 有效设备打开原 Tetra 页面 | `CLOSED → OBSERVING` |
| 观察态左/右键或滚轮命中投影 | 保持 `OBSERVING`，直接映射原 GUI 操作 |
| 观察态按选取方块键 | `OBSERVING → FOCUSED` |
| 聚焦态按选取方块键或 `Esc` | 安全时 `FOCUSED → OBSERVING` |
| 观察态按 `Esc` 或 `E` | `OBSERVING → CLOSING → CLOSED` |
| 服务端或来源硬失效 | 任意活动状态 → `INVALID → CLOSED` |
| 离屏渲染发生不可恢复技术故障 | 活动状态 → 经典故障恢复路径 |

## 8. 世界投影来源与姿态

### 8.1 放置全息球

- 面板从全息球上方展开，发射点与面板底边之间保留细弱灰白光束。
- 初次打开时面向交互玩家，之后只允许有限角度的缓慢转向补偿。

### 8.2 手持全息球

- 发射中心为相机位置沿当前视线前方 `1.25` 格，不再继承手部横向位置、左右手镜像或手部摆动。
- 面板平面始终与相机平面平行，并显式去除滚转；玩家转头或俯仰时页面保持水平直板，不产生斜切和透视压缩。
- 水平避让固定为 `0`；只沿面板屏幕上方向抬高 `0.22` 格，避免第一人称全息球遮住正文。
- 面板仍是参与深度测试的世界四边形，可被近处方块遮挡，但视觉位置随相机保持在正前方，不再追求手部视差。
- 因准星相对该面板基本固定，手持完整页面默认通过选取方块键进入 `FOCUSED` 后使用鼠标操作。

### 8.3 Tetra 工作台

- 面板位于工作台远离玩家的一侧上方，避免遮住台面目标物品和加工演出。
- 面板姿态在会话建立时确定，并与工作台保持稳定空间关系。
- 工作台与面板之间使用轻量灰白连线说明全息方案来源。

### 8.4 共同约束

- 面板为真实世界四边形，参与深度测试并可被实体方块遮挡；手持模式只是让该四边形随相机更新，不另画二维 HUD。
- 面板不具备实体碰撞，也不允许隔墙点击。
- 使用当前渲染帧的真实投影矩阵和相机姿态，覆盖动态 FOV、疾跑、望远镜、受伤视角和窗口比例变化。
- 放置设备可为可读性提供有限物理尺寸补偿，但不能无限朝相机缩放；手持模式按 8.2 的固定前向距离处理。

## 9. 原 GUI、Menu 与离屏目标复用

V1 不重新实现 Tetra 页面。原 Screen 或 mutil GUI 的最终绘制结果进入带透明通道的离屏 `RenderTarget`，再作为世界面板纹理。

原页面继续负责：

- 页面创建、返回与切换。
- 槽位、按钮、筛选、分页和滚轮处理。
- Tooltip、选中态、禁用态与错误原因。
- ItemStack、属性 Bar、材料预览和 Tetra Insight 扩展内容。
- 原容器的网络同步和制作确认。

实现约束：

1. retained Screen 与 Menu 在观察和聚焦之间不得重建。
2. 离屏目标在 GUI 正交投影阶段更新；世界渲染可使用上一帧完成的纹理，避免在透视矩阵阶段错误绘制 Screen。离屏 pass 只调用 retained Screen 自身的 `renderWithTooltip`，不得触发 Forge GUI layers 或 `ScreenEvent.Render`，避免把 JEI 等全局覆盖层烘入投影纹理。
3. 离屏绘制必须保存并恢复 framebuffer、viewport、投影矩阵、scissor、blend、depth 与颜色状态。
4. 使用专用缓冲或只结束本投影的 `RenderType` batch，禁止无参数冲刷全局 buffer source。
5. 窗口缩放、GUI Scale、资源或语言重载后重建目标和坐标缓存。
6. 观察态仍需驱动原页面必要的 tick 与数据刷新；聚焦态不得重复 tick。
7. 主面板捕获区在一次布局周期内保持固定；Tooltip 最终矩形单独记录，绝不能与主捕获区 union，否则长 Tooltip 会改变面板尺寸并造成 Hover 抖动。
8. Tooltip 仅在投影离屏 pass 中限制最大宽度并调整自身锚点，同时保留其他模组提供的更小限制；不得关闭 Tetra 或 mutil 的列表裁剪来换取可见性。
9. 世界姿态、主纹理 UV 与输入映射始终使用固定主捕获区；主区外的 Tooltip 像素按同一 world-per-pixel 映射为独立子平面，因此出现或消失不得改变正文位置。
10. Tooltip 子平面不参与点击、射线命中或可交互区域计算；普通命中仍限制在原页面 `contentBounds`。

### 9.1 离屏纹理布局与裁剪

- `captureBounds` 是稳定的页面几何与输入映射范围；`textureBounds` 只描述本次离屏纹理实际需要覆盖的像素，两者不得互相替代。
- FBO 按 `textureBounds` 分配，而不是按物理窗口全屏分配；`projectionResolutionScale` 只改变离屏像素密度，不改变世界面板尺寸、Tooltip 布局或点击坐标。
- 离屏 pass 使用相对 `textureBounds` 的局部正交投影；所有嵌套 Scissor 必须通过自有栈映射到局部 framebuffer，避免继承主窗口坐标后错误裁剪页面。
- Tooltip 超出当前纹理时允许在同一帧扩张 `textureBounds` 并重绘，最多进行三次有界回退；超出内容消失满 `30` 个实际离屏渲染帧后再收缩，避免瞬时抖动和长期占用峰值尺寸。
- 世界面板和输入映射继续使用稳定的 `captureBounds`；采样 UV 才换算到 `textureBounds` 局部坐标，因此 Tooltip 扩缩不能移动正文、槽位或准星命中点。

### 9.2 自适应刷新缓存

- 世界四边形、姿态、深度和准星命中每帧更新；只有昂贵的 retained Tetra Screen → FBO 绘制允许复用上一张纹理。
- 默认 `AUTO`：携带物品或拖拽时逐帧刷新，页面活跃时最高 `60 Hz`，静止时 `30 Hz`；另提供 `FPS_30`、`FPS_60` 和 `UNLIMITED`。
- 缓存不得跳过会改变可见结果的首次 Hover、Tooltip 扩容、页面切换、容器同步、窗口/GUI Scale 变化或资源重载；这些事件必须使离屏目标立即失效并重绘。
- 默认 `projectionResolutionScale = 1.0` 保持文字清晰；允许配置 `0.5–1.0`，低倍率是用户主动选择的清晰度与 GPU 成本交换，不作为自动动态分辨率。

## 10. 射线、UV 与输入映射

统一坐标链为：

```text
相机/鼠标光标射线
    → 世界投影平面交点
    → 面板 UV
    → 离屏内容矩形
    → 原 Tetra GUI 坐标
```

共同规则：

- 设备锚定投影的观察态使用准星中心射线；聚焦态使用窗口光标经真实相机矩阵反投影得到的射线。
- 手持投影随相机固定在正前方，观察态准星只会命中页面同一位置；其余控件通过聚焦态鼠标射线操作。
- 面板交点必须位于相机前方，并与世界方块命中距离比较，禁止点击被墙体遮挡的控件。
- 普通悬停和进入聚焦要求交点位于投影内容范围内。
- 鼠标按下后，拖拽与释放允许继续映射到无限延伸的投影平面，不把坐标强行裁回面板边缘，以保留原 GUI 的拖出、快速分配和释放语义。
- 点击、释放、拖拽增量、滚轮、Tooltip 和高亮必须使用同一套 UV 到 GUI 变换。
- 无交点、背面、来源失效或遮挡时返回明确失败，不把事件发送给错误槽位。

应为平面相交、UV 映射、GUI 往返、背面、平行射线、遮挡和拖拽越界建立无游戏环境单元测试。

### 10.1 工作台世界快捷交互

完整页面仍保留所有复杂选择，但常用物流与单一加工动作可直接在世界中完成：

- 手持模块化装备右键空工作台，将待改造物放入目标槽。
- 手持唯一合法材料右键工作台，通过原 `WorkbenchContainer` 点击链投入对应材料槽；多个槽同时合法时不猜测，提示打开投影选择。
- 手持满足要求的工具右键工作台，仅在制作或维护候选唯一时调用 Tetra 原 `initiateCrafting` 或 `performAction`；候选有歧义时回到投影。
- 潜行右键工作台用于取回已投入内容。执行前先模拟玩家背包容量，必须能完整容纳所有待取物品才继续。
- 取回时先通过原容器 `QUICK_MOVE` 依次移出材料槽，最后才移出目标槽；Tetra 在目标槽变化时会自动清空材料，因此反向顺序可能把材料作为实体丢出。
- 所有快捷操作都验证当前 `WorkbenchContainer`、`WorkbenchTile` 对象身份、距离与容器有效性，并对一次物理按键加锁，避免主副手重复事件和长按连点。

这些快捷操作只缩短交互路径，不直接写客户端 ItemHandler，不改变原配方、NBT、材料、经验、工具消耗或服务端结算。

## 11. 黑白灰视觉与可读性

### 11.1 视觉语言

- 背板使用半透明煤黑或深灰，不使用蓝青色科幻面板。
- 主边框、文字与激活项使用白色；次级结构使用浅灰；禁用项使用中灰虚线或短暂扫描断层。
- 危险或失效状态使用白灰闪断、缺口和收束动画，不引入彩色警告遮罩。
- 投影只保留很弱的白色边缘辉光，不使用持续闪烁、色散、字符雨或强扫描线。
- 页面结构保持黑白灰；真实物品、材料和工具图标可保留原贴图颜色，以免损失识别功能。

### 11.2 阅读约束

- 默认保留原 GUI 的逻辑布局，不压缩卡片、槽位或文字来塞入更小面板。
- 文本与关键槽位背后保持足够不透明度，不能因“全息透明”而看不清。
- 正文四周保留 `16` GUI 像素的黑色背板留白；低分辨率下纹理捕获区可以裁到窗口边缘，但背板几何仍应尽量保住正文呼吸空间。
- 面板距离过远时先限制聚焦并提示靠近；不能直接跳成普通全屏菜单。
- Tooltip 属于世界投影内容，可在同一平面或轻微前移的独立子平面显示，不重新绘制为普通 HUD；长 Tooltip 应换行并优先移动到固定主捕获区内，仍然外伸的部分单独采样，不能改变主面板尺寸或被原页面边界截断。
- 提供投影物理尺寸、背板不透明度、边缘亮度、动画强度、粒子数量和声音音量配置。
- “减少动态效果”关闭位移、工具大幅轨迹和粒子，只保留短淡入、状态线条与声音。
- 不使用颜色、粒子或声音作为唯一状态提示；所有制作条件仍由原 GUI 文本和图标表达。

## 12. 锻造演出

### 12.1 核心原则

锻造演出是结算后的本地表现，不是制作流程本身。玩家点击原 Tetra 确认控件后，原数据包按原时机发送，服务端照常完成材料消耗和结果写入。新附属不得取消该点击、缓存制作请求、延迟网络包、再次调用制作逻辑或修改容器槽位。

客户端通过原菜单内容、目标 ItemStack/NBT 或页面结果的已确认变化建立只用于渲染的 `PresentationSnapshot`：

- `before`：确认前用于展示的物品副本。
- `after`：服务端同步后的结果物品副本。
- `context`：当前 schematic、模块、工具需求、实际工具提供方及工作台位置的只读信息。
- `transactionKey`：用于去重的菜单、槽位、物品签名与时间窗口。

实际物品始终以服务端同步结果为准。关闭投影、资源重载或演出异常时，立即结束表现并显示真实结果，不能回滚、补扣或重复生成物品。

### 12.2 工艺分类

优先从 `UpgradeSchematic#getRequiredToolLevels(target, materials)` 和当前工作台工具提供方取得实际 `ToolAction`，不能只按 schematic 名称猜测。

| 工艺上下文 | 建议表现 |
|---|---|
| 锤类需求 | 物品压低、1–3 次短锤击、材料对应音色、少量火花或碎屑。 |
| 切削需求 | 方向明确的切削轨迹、短刮削声、木屑、石粉或金属火星。 |
| 撬拆需求 | 模块边缘先抬起，再脱离并伴随卡扣声。 |
| 打磨/维护 | 连续但低幅度的摩擦光带、音高渐升、末端稳固提示。 |
| 固定、缠绕或装配 | 模块幽灵对齐、卡扣或绑缚声、边缘逐段锁定。 |
| 无明确工具的普通更换 | 快速拆卸、对齐、嵌入和全息校准，不播放重锤动画。 |
| 附魔或魔力改进 | 灰白符文沿模块轮廓收束，保持短促且不遮挡属性结果。 |

单次演出采用“侧移 → 停稳 → 加工 → 结果停留 → 回位”的明确节奏：

- 侧移 `420–500 ms`，默认移动约 `208–248 px`，按当前投影比例约为 `1.13–1.34` 格；实际位移至少为捕获面板宽度的一半再加 `16 px`，确保背板边缘越过工作台中心。
- 停稳 `150–180 ms`；工具、台面物品、声音与粒子尚不播放。
- 加工 `480–820 ms`；只有面板完全让开并停稳后才同时开始工具动作、物品动作、声音与粒子。
- 结果停留 `520–700 ms`，面板继续保持最大位移，让玩家看清台面与结果。
- 回位 `480–560 ms`，结束后不保留偏移。

演出不阻塞继续操作。连续结算时同一工作台的旧延迟效果与旧演出会被最新事务替换，避免队列积压或稍后播放过期声音；无同源投影、减少动态或位移为零时立即播放加工反馈。

### 12.3 台面与工具来源

- 复用 Tetra 已有工作台目标物品与锻造锤渲染语义，不替换对应 BlockEntity 或 Renderer。
- 工具动画应来自 Tetra 实际选择的相邻工具提供方或真实手持工具，不能从背包任取一件工具并悬浮在台面上。
- 工作台演出只增加局部物品姿态、工具轨迹、声音和粒子；不得让同一物品被两个渲染器同时完整绘制。
- 悬挂锻造锤已有动画时，以监听和增强为主，不重新创建另一套锤击进度。
- V1 效果只保证本地操作者可见；其他玩家所见仍由 Tetra 原有同步决定。

## 13. 技术模块建议

| 模块 | 责任 |
|---|---|
| `ProjectionSession` | 持有 retained Screen/Menu、状态、来源、离屏目标与关闭原因。 |
| `ProjectionOriginResolver` | 为放置全息球、手持全息球和工作台解析真实世界发射源。 |
| `WorldPanelPose` | 保存面板中心、右向量、上向量、法向量和物理尺寸，并提供手持投影的无滚转相机平行姿态。 |
| `GuiBounds` | 描述原页面内容、固定主捕获区和独立 Tooltip 区域，并提供相交与矩形差集。 |
| `ProjectedScreenTarget` | 承载原 GUI 的透明离屏绘制、固定主捕获区、每帧 Tooltip 区域列表和 framebuffer 生命周期。 |
| `ProjectionTextureLayout` | 分离稳定 `captureBounds` 与局部 `textureBounds`，计算 FBO 尺寸、Tooltip 扩缩和 UV。 |
| `ProjectionScissorStack` | 将原页面的嵌套 Scissor 映射到局部 framebuffer，并在离屏 pass 后完整恢复。 |
| `ProjectionRefreshLimiter` | 根据交互状态、脏标记和刷新模式决定是否重绘 FBO；不限制世界四边形更新。 |
| `PanelInputMapper` | 完成相机或鼠标射线、平面交点、UV 与 GUI 坐标映射。 |
| `WorldProjectionRenderer` | 绘制深度正确的主面板、Tooltip 子平面、背板、边框、发射连线和关闭动画。 |
| `ProjectionLifecycleController` | 执行观察、聚焦、失焦、关闭、失效和经典故障恢复。 |
| `CraftObservationService` | 只读观察确认前后菜单或物品变化并去重。 |
| `ForgePresentationController` | 根据只读上下文播放、收束或取消本地演出。 |
| `TetraCompatFacade` | 隔离 Tetra 6.9.x 的版本敏感访问并集中处理可选附属检测。 |

Mixin 应优先落在最外层 Screen 生命周期、最终绘制入口、鼠标坐标调用点或只读访问器。页面内部布局不得成为 V1 的常规注入点。

## 14. 生命周期与经典故障恢复

经典全屏 GUI 只用于以下不可恢复技术故障：

- framebuffer 创建、绑定或恢复失败。
- 目标 Tetra Screen 签名或兼容访问器失效。
- 光影环境持续破坏离屏纹理或世界面板绘制。
- 输入变换出现违反不变量的错误，可能把点击发送到错误槽位。

经典故障恢复不是普通状态：

1. 不提供“记住经典模式”或普通热切换配置。
2. 恢复时沿用 retained 原 Screen 与 Menu，不重新发送打开请求。
3. 使用一次性 pass-through 标记，允许原 Screen 完成 Opening 与 Init；标记只能在对应 Init 完成后清除，防止再次建立世界投影形成循环。
4. 距离、遮挡、转头或暂时无法命中面板不得触发经典恢复。
5. 故障恢复失败时优先关闭当前菜单并释放输入，不能把玩家留在看不见又无法退出的状态。

## 15. 兼容策略

### 15.1 Tetra Insight 与 ExtraHoloPage

当前 Tetra Insight 与 ExtraHoloPage 会修改 `HoloImprovementGui`、`HoloMaterialApplicable`、`HoloSchematicGui` 和 `HoloVariantDetailGui`。新附属必须把这些模组完成后的最终页面整体写入离屏目标，禁止再次计算改进卡宽度、材料行数、筛选分页或详情页布局。

兼容规则：

1. 不向上述页面类加入布局重排 Mixin。
2. 不通过 Mixin 优先级赌加载顺序；必须访问字段时使用只读 accessor，并限制目标版本。
3. Tetra Insight 存在时，投影中完整保留搜索、分页、材料影响、改进详情和动态属性 Bar。
4. ExtraHoloPage 存在时，以其最终行数和间距为准；投影层不做二次压缩。
5. 检测到已知重叠附属时给出一次明确警告，不得静默丢失按钮或分页。
6. 兼容探针失败才进入经典故障恢复，不能阻止游戏启动或工作台使用。

### 15.2 其他客户端环境

- Tetra View 的 `V` 键和独立 Screen 保持不变。
- 验证 Embeddium/Oculus、无光影与启用光影时的离屏透明、深度、ItemStack 光照和面板混合。
- 默认不修改 FOV、鼠标灵敏度、相机模式或客户端暂停规则。
- 客户端加入未安装本附属的专用服务器后仍可正常打开 Tetra 页面并制作。

## 18. V1 验收标准

1. 打开工作台或全息球后直接出现真实世界投影，不出现普通全屏 GUI 闪帧或黑色遮罩；只有手持全息球按设计随视野固定在相机正前方。
2. `OBSERVING` 状态下可正常移动、跳跃、疾跑、潜行和自由转头；所有投影保持世界深度，放置设备保持来源关系，手持投影保持正前方无滚转姿态。
3. `FOCUSED` 状态下仍只显示世界投影；原 Tetra Screen 接收输入，但不在主画面绘制普通菜单。
4. `Esc` 严格执行 `FOCUSED → OBSERVING`，再次 `Esc` 才关闭；第一次不得发送容器关闭包或执行 HoloGui 关闭回调。
5. 观察与聚焦之间不重建 Screen/Menu，不丢失页面、筛选、选材、悬停、carried stack 或已选方案。
6. 投影可完成与原 GUI 等价的页面导航、点击、Shift 点击、拖拽、拖出释放、滚轮、Tooltip、键盘输入、确认与关闭操作。
7. 手持全息球位于相机前方 `1.25` 格、无水平偏移、无滚转，并保留世界深度；完整页面可通过选取方块键进入鼠标模式操作。
8. 页面结构遵循黑白灰视觉；文字与槽位清晰，实际物品和材料仍可辨认。
9. 距离、遮挡或转头只改变设备锚定投影的观察与聚焦资格，不自动显示经典全屏 GUI；手持投影转头时继续跟随视野。
10. 经典故障恢复只由不可恢复技术错误触发，并且不会再次捕获自身形成循环。
11. 一次制作仍只产生一次 Tetra 原请求和一次服务端结算；新附属不写入槽位或物品 NBT。
12. 普通更换、锤击、切削、撬拆、打磨和装配具有不同短反馈，不把所有动作统一成锤击。
13. Tetra Insight 与 ExtraHoloPage 页面无新增布局覆盖、按钮缺失、Mixin 注入失败或启动崩溃。
14. GUI Scale 2/3/4、中文/英文、长 Tooltip、光影开关和未安装本附属的专用服务器均有实际交互回归记录。
15. 默认 `AUTO` 下，世界面板仍逐帧跟随视角；离屏页面静止时可复用纹理，交互、拖拽、Tooltip 与容器变化时不得出现可感知的输入延迟或陈旧画面。

## 19. 后续双端扩展边界

未来若加入真实挥锤输入、多人可见动作、工序暂停、协作加工或服务器权威耗时，应作为 V2 双端协议单独设计。V2 仍须让 Tetra 的 `canApplyUpgrade`、材料消耗和 `craft()` 保持最终权威，只在已获服务器许可的制作事务外层增加同步演出或工序状态，不能复制一套可能随 Tetra 漂移的制作规则。

V1 的 retained Screen/Menu、世界投影、FBO、射线映射和表现控制器可以继续复用，但纯客户端演出与服务器权威工序必须保持明确分离。
