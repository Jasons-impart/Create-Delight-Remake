## 酿造归属

以统一酒类清单中的容器为依据分配生产体系，妖怪归家作为保留例外。

| 分组 | 当前数量 | 生产规则 |
|---|---:|---|
| 使用 `brewinandchewin:tankard` 的酒 | 31 | 保留 B&C 发酵桶，删除直接产酒的 Create/CDG 发酵旁路 |
| 妖怪归家的现行酒 | 13 | 保留现有酿造体系 |
| 其他现有酒及森罗自带酒 | 现有18项＋森罗酒 | 迁入森罗酒桶或调酒器 |

- 保留瓶液互转、倒酒和物流功能；旧工作站的非酒配方继续使用。
- 迁移组的魔法、怪物和加热前置保留；必要时改为制作待酿基液，最终成品必须经过森罗设备。
- 妖归本轮不补放置模型。其他迁移酒支持原物品出料，保留原 ID，不以新增放置模型作为迁移前提。
- 两款获取来源未确认的酒——附魔大都会鸡尾酒、墨汁啤酒——保留归属和兼容登记，本轮不擅自新增获取方式；已移除的五款妖归葡萄酒不恢复。

## 森罗酒桶：整桶投入、整批完成

- 容量维持 **4000mB**。必须满桶且具备整批材料，才能开酿；普通酒整批产出 **16瓶，每瓶250mB**。
- 扩展配方原料计数，按整批需求精确扣料。多余材料保留，不再依赖原生“按最少原料数量决定产量”的逻辑。
- 发酵开始后锁定本批酒液和材料，禁止补液、抽液和提前取酒；达到发酵时间后，整批成品一次完成。
- 完成后允许分次取酒；剩余成品取空前，不接受下一桶酒液。缺少空容器只阻止装瓶，不影响发酵完成。
- 补齐泵进料、漏斗投料、供瓶和取成品接口；手动龙头与自动出料共享批次、品质和容器逻辑。
- 保存批次状态、计时、基础品质和剩余产量，卸载区块、重启及部分出料均不能复制产物或重新计算品质。

**烈焰麦酒新增配方默认值：**4L B&C 啤酒＋4烈焰粉＋4下界疣＋4奥术精华，发酵4800刻，产16瓶；保留现有战利品额外来源。

## Create 存量转信器

通过 CDC 为森罗酒桶实现 `ThresholdSwitchObservable`，仅报告发酵完成后的成品酒量：

- 最小值0、最大值4000；进料和发酵期间读数为0。
- 发酵完成后为4000；每取一瓶减少250，取空后归零。
- 缺空瓶时仍计为成品库存；辅料、空瓶和未完成批次不参与统计。
- 仅对森罗酒桶修正 Create 的目标类型识别优先级，保证自定义读数显示为 mB，避免物品与流体相加或单位错误。
- 沿用转信器原有更新频率、上下阈值和红石行为。

## QF、调酒与醉酒

- QF 完全替代 `BrewLevel`。扣料时按实际投入调用现有 QFF 规则，一次确定基础品质，同批一致。
- 发酵完成即可取酒；额外陈酿 **12000刻（10分钟）**，剩余成品最多提升一级，最高钻品质。不增加成品回灌陈酿配方。
- 调酒器扩至六格，放置后约五秒制作；手持和放置模式共享配方、品质及容器返还。酒类基料至少金品质，非酒辅料不受此门槛限制。
- 普通森罗酒取原生第三档作为基础特色效果，固定鸡尾酒保留单档效果；通过 CDC 应用一次 QF 增益。
- 统一醉酒继续使用妖归 `drunk`：普通、铁、金、钻对应I～IV，取消续杯升级。镜头与行走偏移共同反向，保留原生平滑、三秒周期和平方曲线；镜头最大30°，I～V稳定峰值依次为 **30°、16.875°、7.5°、1.875°、0°**。
- 屏幕特效强度正向控制镜头和走偏，设零时两者关闭。保留妖归攻击加成和清醒体系，醉酒不重复套用 QF 增益。
- 默认最近一杯决定等级，时长取当前剩余与本杯时长的较大值，不累加。普通酒30秒，神秘鸡尾酒180秒；原本无醉酒的森罗固定鸡尾酒保持原设定。
