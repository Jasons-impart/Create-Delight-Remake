# 品质收割与生命质回收设计

本文记录品质原材料自动化的设计方向：生命质只能通过带 Quality Food 品质的物品提取获得，带品质的原材料只能在改进收割机或动态结构机械手收割时消耗生命质生成。

## 设计目标

- 允许玩家建设真正可运行的品质原材料农场。
- 保留“品质物品不能被普通配方随意自动化产出”的原则。
- 让手动育种、耕地、季节、温室和作物地块品质仍然有价值。
- 尽量复用 Create 收割机和现有 Quality Food 计算逻辑，避免新增多套行为相近的收割机器。

## 非目标

- 不通过静态 KubeJS 配方直接输出带品质 NBT 的物品。
- 不让普通机械收割机在无额外成本时产出品质。
- 不模拟玩家幸运，也不让 FakePlayer 等价于真实玩家手动收获。
- 第一版不要求生命质承载品质等级；生命质只是自动化品质收割的消耗资源。

## 核心结论

品质自动化拆成两部分：

1. 生命质回收：由带品质物品提取获得，品质越高回收越多。
2. 品质收割自动化：改进后的 Create 收割机或动态结构机械手在收割成熟作物时消耗生命质，并按作物环境与地块品质进行品质判定。

换句话说：

> 生命质是机器获得品质判定资格的燃料，不是品质物品本身。

## 玩家流程

早期：

- 玩家手动种植和收获，获得第一批品质作物。
- 通过季节、合适湿度、优质耕地和作物品质积累，提高田地品质生态。

中期：

- 玩家使用品质吸收器，将带品质物品提取为 `createdelight:life_matter`。
- 玩家制作生命质萃取仓，将带品质物品自动消耗并回收为 `createdelight:life_matter`。
- 玩家制作 `生命质校准器 I`，把它放入移动结构或随车库存。
- Create 收割机或动态结构机械手检测到校准器和生命质后，开始消耗生命质尝试产出品质原材料。

后期：

- 玩家升级校准器，提高机器倍率、品质上限和生命质利用率。
- 玩家建设温室、稳定季节/湿度、特殊耕地和高品质种田区，让自动品质收割更稳定。
- 品质原材料进入食品加工、订单、售卖或后续品质传播链。

## 生命质回收

生命质应是普通物品，第一版不做流体。

原因：

- 移动结构和 Create 收割机更容易从随车物品库存消耗物品。
- 物品配方、任务和 JEI 展示更直接。
- 避免流体 NBT、混合、管道缓存和移动结构液体访问带来的复杂度。

推荐物品：

| 物品 | 定位 |
|---|---|
| `createdelight:life_matter` | 品控收割消耗品，生命质第一版唯一正式资源 |
| `createdelight:crude_life_matter` | 可选，作为低级中间材料或早期产线缓冲 |

推荐产出方向：

| 输入方向 | 工艺 | 输出 |
|---|---|---|
| 铁品质物品 | 品质吸收器提取 | 少量生命质 |
| 金品质物品 | 品质吸收器提取 | 中量生命质 |
| 钻石品质物品 | 品质吸收器提取 | 大量生命质 |

生命质不再由普通有机物、堆肥或 `createaddition:biomass` 直接产出。品质收割可以形成“品质物品 -> 生命质 -> 品质收割”的循环，但循环需要先获得品质物品，且每次机器收割仍消耗生命质。

自动回收第一版使用 MBD2 单方块机器 `createdelight:life_matter_extractor`（显示名：生命质萃取仓）承载。它每 200 tick 从 `item_input_slot` 寻找一批带品质物品，按品质等级向 `item_output_slot` 产出生命质，并消耗这些物品本体。单次最多处理 8 个物品，钻石品质批处理最多输出 48 个生命质，降低动态结构持续输出造成的堵塞风险：

| 输入品质 | 自动萃取产出 |
|---|---:|
| 铁品质 | 1 个生命质 |
| 金品质 | 3 个生命质 |
| 钻石品质 | 6 个生命质 |

手动品质吸收器仍保留“移除品质、保留物品”的定位；自动机器则消耗物品本体，避免全自动链路把高品质原材料免费降级成普通原材料副产物。

## 收割机升级件

不建议新增多种收割机方块。推荐保留 Create 原收割机，新增多级品控升级件。

升级件可作为普通物品存在于移动结构库存中，也可以后续改为必须安装在特定方块上。第一版建议检测库存物品，成本最低。

升级件应采用标签驱动。CDC 不应硬编码具体升级件物品 ID，只识别标签对应的能力档位；KubeJS、数据包或兼容补丁负责把具体物品加入标签。

| 升级件 | 生命质消耗 | 品质上限 | 机器倍率 | 定位 |
|---|---:|---:|---:|---|
| 生命质校准器 I | 2 / 次收割 | 铁品质 | 0.25 | 中期入门，主要用于把手动积累扩展为低级品质产线，不应稳定正收益 |
| 生命质校准器 II | 3 / 次收割 | 金品质 | 0.45 | 稳定农场核心升级，优秀环境可接近持平或小幅正收益 |
| 生命质校准器 III | 5 / 次收割 | 钻石品质 | 0.70 | 后期温室与高品质订单配套，高投入设置允许形成明确正收益 |

推荐标签契约：

CDC 当前读取 `createdelightcore:*` 标签；整合包侧可以同时维护同名 `createdelight:*` 桥接标签，方便任务、tooltip 和后续数据包兼容。

| 标签 | CDC 含义 |
|---|---|
| `#createdelightcore:quality_harvest_calibrators` | 任意品控收割升级件的总标签，用于 tooltip、任务和兼容筛选 |
| `#createdelightcore:quality_harvest_calibrators/tier_1` | 生命质消耗 2，品质上限为铁品质，机器倍率 0.25 |
| `#createdelightcore:quality_harvest_calibrators/tier_2` | 生命质消耗 3，品质上限为金品质，机器倍率 0.45 |
| `#createdelightcore:quality_harvest_calibrators/tier_3` | 生命质消耗 5，品质上限为钻石品质，机器倍率 0.70 |
| `#createdelightcore:life_matter` | 可被品控收割消耗的生命质物品 |

如果同一移动结构库存中存在多个升级件，CDC 采用最高 tier。生命质消耗仍按最高 tier 执行，避免玩家用低级耗材触发高级倍率。

规则：

- 无校准器：不消耗生命质，不产出品质。
- 有校准器但无生命质：正常无品质收割。
- 有校准器和生命质：每个成熟作物收割时消耗生命质并进行一次品质判定。
- 动态结构机械手右键收割作物时使用同一套自动品质判定；固定 Deployer 不应在没有控制器/注入器等明确生命质来源时获得品质。
- 自动收割不吃玩家幸运。
- 自动收割的品质上限受校准器等级限制。

## 动态结构库存治理

Create 动态结构的整车库存适合作为物流空间，但不适合作为精确机器配置界面。若长期依赖“扫描整车任意库存”来寻找生命质和校准器，会出现几个问题：

- 玩家很难控制生命质具体从哪里被消耗。
- 大型农场、随车仓库和产物缓存会混在一起，调试成本高。
- 多个收割区域共享同一整车库存时，不容易为不同区域设置不同校准器等级。
- UI 和任务引导难以解释“为什么这个收割机没有产出品质”。
- 如果通过移动式储物接口持续输入生命质，生命质作为普通物品会占用整车产物空间；补给过量时最终可能挤爆作物输出缓存。

因此整车库存扫描只适合作为简易验证和兼容 fallback。正式方案不应让生命质通过移动式储物接口进入整车普通物品库存，而应把补给拆成“固定端注入器”和“车载控制器内部储量”两部分。

配套方块方向：

| 方块方向 | 定位 |
|---|---|
| 品控收割控制器 | 已在 CDC 接入第一版；安装在动态结构上，保存校准器和内部生命质储量，供同车品控收割消耗 |
| 生命质注入器 | 已在 CDC 接入第一版；放在固定基地端，停靠时消耗自身输入槽中的生命质并给车载控制器充能 |

当前/正式规则：

- 如果同一动态结构上存在品控收割控制器，CDC 优先从控制器读取校准器和内部生命质储量。
- 控制器存在时，不再扫描整车普通库存，避免误吃仓库里的生命质；控制器缺校准器或生命质不足时，本次收割直接走无品质结果。
- 如果没有控制器，才回退到当前“整车库存扫描”的简易模式。
- 第一版控制器提供 `校准器槽`、内部生命质储量、右键状态提示和红石比较器容量输出；后续可扩展 `作物过滤槽`、`策略槽`、Jade 或 GUI。
- 第一版控制器容量为 512 点生命质，右键持有 `#createdelightcore:life_matter` 可充入，右键持有 `#createdelightcore:quality_harvest_calibrators` 可安装校准器，空手潜行右键可取出校准器。
- 生命质注入器只在动态结构停靠或可访问时工作，从自身输入槽消耗 `#createdelightcore:life_matter`，把数量写入车载控制器内部储量。
- 生命质注入器应尊重控制器容量上限；控制器满时停止注入，不把多余生命质塞进动态结构普通库存。
- 移动式储物接口仍只负责作物产物和普通物流，不承担生命质长期补给职责。

这样能让 Create 原版收割机继续承担“收割”职责，移动式储物接口继续承担“产物交换”职责，而品控能力和生命质补给由专门的控制器/注入器处理。相比新增多种收割机方块，这套方案更容易兼容既有机械动力结构，也能避免生命质占用作物输出空间。

### 生命质注入器停靠判定

生命质注入器的“停靠”应复用玩家对 Create 移动式储物接口的直觉：结构接近固定端、方向对齐、进入短暂对接窗口后才传输。停靠不是要求动态结构永久静止，而是一次可识别的对接过程。

第一版推荐条件：

- 固定端方块为生命质注入器，且未被红石禁用。
- 动态结构上存在品控收割控制器；后续可扩展为车载生命质接收口。
- 注入器正前方约 0.25-3.25 格范围内存在动态结构上的目标方块，横向容差约 1.25 格；第一版直接对接品控收割控制器，不要求控制器自身有朝向。
- 动态结构实体仍然有效，且本 tick 可以访问其 `contraption.getBlocks()` 数据。
- 目标控制器内部生命质储量未达到容量上限。
- 注入器输入槽中存在 `#createdelightcore:life_matter`。

满足以上条件时，注入器进入对接窗口：

- 每 tick 检测一次对接窗口，避免动态结构经过时错过低频扫描；成功对准后用短冷却控制注入频率，当前每 5 tick 最多注入 16 点生命质。
- 注入时直接写入车载控制器的方块实体 NBT，例如 `LifeMatterStored`，不向动态结构普通物品库存插入生命质物品。
- 单次注入量不能超过控制器剩余容量；控制器满时立即停止。
- 如果动态结构已经离开对接范围、朝向不再匹配、注入器断红石或输入槽耗尽，则结束对接。
- 第一版不主动停顿动态结构，只在结构自然经过对接范围时尝试注入；后续可加短暂停顿，让行为更接近移动式储物接口。
- 注入器模型应明确显示正面，右键状态应显示朝向、对接状态和目标控制器容量，避免玩家无法判断是否真正对准。

为避免玩家必须把控制器暴露在车体边缘，长期可以新增车载生命质接收口：

```text
固定端生命质注入器 <-> 车载生命质接收口 -> 同车品控收割控制器
```

当前第一版允许注入器直接对接品控收割控制器；接收口作为后续扩展，用于把外部对接口和内部控制器分离。

## 品质判定

推荐复用现有 Quality Food 与 CDC 的品质计算思路，但加入自动化上下文。

判定输入：

- 作物方块和成熟状态。
- `LevelData` 中该作物地块的品质。
- 作物下方有效耕地。
- 季节和湿度环境。
- 校准器等级。
- 生命质是否成功消耗。

推荐公式思路：

```text
自动品质概率 = 原品质概率 * 环境修正 * 机器倍率
```

其中：

- 原品质概率来自 Quality Food 的基础品质概率与作物地块品质。
- 环境修正沿用当前季节/湿度和耕地逻辑。
- 机器倍率由校准器等级决定。
- 玩家幸运不参与。
- 自动收割不使用手动收获的额外环境宽容系数；温室和月壤仍然重要，但不应让最低级校准器在理想环境下稳定产出更多生命质。

额外限制：

```text
最终品质等级 <= 校准器品质上限
最终品质等级 <= 作物地块品质 + 1
```

最高级校准器可以放宽第二条限制，但仍需要生命质和优秀环境支撑。

## 与手动收获的关系

手动收获仍应更适合育种和突破：

- 手动收获可吃玩家幸运。
- 手动收获不消耗生命质。
- 手动收获适合建立第一批高品质田地。

自动收获更适合规模化：

- 自动收获需要持续生命质供应。
- 自动收获概率低于手动。
- 自动收获由工程规模、环境建设和升级件补偿效率。

这样可以形成清晰分工：

> 手动负责育质，生命质负责供能，品控收割负责规模化。

## 生命质扩展用途

生命质可以继续扩展，但应保持一个核心身份：

> 生命质是高品质农业产物沉淀出来的活性信用，不是通用生物质、肥料、燃料或直接赋予品质的万能材料。

因此扩展用途应优先服务于“品质农业生态”本身，避免和 `createaddition:biomass`、堆肥、骨粉或普通经济货币混同。生命质只能从带品质物品回收获得的原则不应被反向入口破坏。

### 遗传种子培养

`Create Mechanical Spawner` 已有遗传种子和刷怪液链路：`inferior_genetic_seed`、`normal_genetic_seed`、`refined_genetic_seed`、`pure_genetic_seed`、`flawless_genetic_seed`。这条线天然接近生命工程，适合让生命质承担“稳定遗传表达”的催化剂角色。

生命质不应直接生产刷怪液，也不应替代怪物材料、灵质或随机刷怪液。推荐做法是在既有升级链上增加高成本、高概率的替代配方，或把生命质作为额外输入提高升级成功率：

| 工艺 | 基础定位 | 推荐生命质强化 |
|---|---|---|
| `inferior_genetic_seed` -> `normal_genetic_seed` | 入门遗传种子升级 | 额外消耗 1 个生命质，将概率提高到约 65%-70% |
| `normal_genetic_seed` -> `refined_genetic_seed` | 中级升级 | 额外消耗 3 个生命质，将概率提高到约 70%-75% |
| `refined_genetic_seed` -> `pure_genetic_seed` | 高级升级 | 额外消耗 8 个生命质，将概率提高到约 75%-85% |
| `pure_genetic_seed` -> `flawless_genetic_seed` | 后期稳定化目标 | 消耗 16-24 个生命质和特殊催化物，提供高概率或稳定产出 |

这样生命质会让品质农场反哺生物自动化，但不会让普通生物质、怪物农场或刷怪液系统反过来成为生命质来源。

### 订单封缄

订单系统已经支持质量要求、奖励倍率、声望、市场饱和和订单草稿印章。生命质适合做成订单构筑阶段的高品质修饰物，用来把普通订单推向更高质量、更高收益、更高风险。

推荐新增“封蜡/封缄”类物品，而不是让生命质直接兑换货币：

| 物品方向 | 推荐成本 | 订单效果 |
|---|---:|---|
| 鲜活封蜡 | 4 个生命质 | 小幅提高金钱收益，可能略微提高需求量 |
| 生命质封缄 | 8 个生命质 | `minQualityBonus +1`，提高声望收益 |
| 臻选鲜活封缄 | 16 个生命质 | 更偏向高质量订单，提高金钱和声望倍率，同时提高订单规模或市场压力 |

实现上可以把封缄写入 `OrderDraft` 的修饰信息，再由 `Order.create(player, spec)` 转换为 `minQualityBonus`、`moneyMultiplier`、`reputationMultiplier`、`countMultiplier` 或 `entryCountMultiplier`。订单构筑台只需要预览大致方向，不需要提前展示最终订单。

这条线的设计价值是给生命质提供一个非农业消耗口，同时让高品质原材料通过订单系统变成更清晰的经济目标。

### 暂不推荐：温室与土壤活化

生命质暂不推荐接入温室、土壤或作物生长增益。这个方向虽然能和农业主题相连，但容易把生命质变成高级肥料、骨粉或环境增益材料，削弱“由品质物品回收、用于品质自动化与高阶生物/订单系统”的身份。

尤其不建议做：

- `生命质 -> 活性土壤/培养土 -> 更高品质产出` 的间接赋质链。
- `生命质 -> 温室范围增益` 的被动倍率光环。
- `生命质 -> 加速生长/催熟` 的骨粉替代品。

温室仍然可以作为品质农业的环境建设目标，但它不需要消耗生命质来成立。生命质的扩展主线应先集中在遗传种子培养和订单封缄上。

### 明确不推荐的用途

- 不把生命质做成 `createaddition:biomass`、堆肥、骨粉或任何通用有机燃料的上位替代。
- 不让普通有机物、怪物掉落物或刷怪液直接产出生命质。
- 不做“生命质 + 普通作物 = 带品质作物”的静态配方。
- 不让生命质直接兑换金钱、订单声望或可无限倒卖的高价值物品。
- 不让一次生命质消耗覆盖大面积作物收割，避免绕过单次收割成本。

### 推荐落地顺序

1. 遗传种子培养强化：以配方层改动为主，最容易验证平衡。
2. 订单封缄：接入订单构筑和 `Order.create` 的修饰参数，让生命质成为高品质订单门票。

## 实现草案

KubeJS 侧：

- 在 `startup_scripts/registry_item.js` 注册生命质和默认校准器物品。
- 在服务端 tags 脚本中维护 `#createdelightcore:life_matter` 与 `#createdelightcore:quality_harvest_calibrators/...` 标签；可同步维护 `#createdelight:*` 桥接标签。
- 在 `server_scripts/Quality Food/absorber.js` 中维护品质物品到生命质的提取逻辑。
- 在 `server_scripts/mbd2/life_matter_extractor.js` 中维护生命质萃取仓的自动提取逻辑；由于需要读取品质 NBT，不使用静态配方。
- 在任务线中说明生命质可自动化，但品质只在品控收割时生成。

CDC 侧：

- 新增自动品质收割上下文，例如 `QualityFoodAutomationHarvestContext`。
- 在 Create 收割机行为中，收割前检测移动结构库存中的校准器标签和生命质标签。
- CDC 将 tier 标签映射为消耗、品质上限和机器倍率；不要依赖具体物品 ID。
- 成功消耗生命质后，将自动上下文传入品质计算。
- 修改 `QualityFoodMixin`：当 `player == null` 或 FakePlayer 时，如果存在自动上下文，则使用自动上下文计算；否则仍保持无品质。
- 对 Create 收割机、动态结构机械手、Vinery、蘑菇殖民地、花簇和普通 `CropBlock` 的收割路径补齐品质应用。
- CDC 已新增品控收割控制器并优先读取控制器槽位和内部生命质储量；整车库存扫描保留为无控制器时的兼容 fallback。
- CDC 已新增生命质注入器第一版，固定端注入器负责把物品生命质转换为车载控制器内部储量，避免生命质进入动态结构普通物品库存。

关键边界：

- 不要通过 KubeJS 直接给静态配方输出写品质 NBT。
- 不要让 `player == null` 默认获得品质概率。
- 消耗生命质必须与单次收割绑定，避免一次消耗覆盖大量作物。

## 第一阶段建议

第一版只做最小闭环：

1. 新增 `createdelight:life_matter`。
2. 新增 `生命质校准器 I`。
3. 给生命质和校准器维护标签，CDC 通过标签识别能力。
4. 让品质吸收器把带品质物品提取为生命质，不提供普通静态配方。
5. 接入生命质萃取仓，允许玩家把品质物品自动消耗为生命质。
6. 让 Create 收割机和动态结构机械手在检测到校准器标签和生命质标签时，对普通成熟作物消耗生命质并尝试产出最高铁/金/钻石品质。

后续改进：

- 为品控收割控制器补充更完整的 GUI/Jade/Ponder 引导，展示档位、单次消耗、内部生命质储量和剩余可收割次数。
- 为生命质注入器补充更完整的外观、Ponder/Jade 引导和可选短暂停顿对接行为。
- 继续保留“有控制器只读控制器、无控制器才扫描整车库存”的规则。
- 生命质注入器不应把多余生命质输入动态结构普通库存，避免挤占作物产物空间。
- 任务、tooltip 或 Ponder 应把控制器作为推荐玩法，把整车库存扫描描述为简易/兼容模式。

先不做：

- 多级生命质。
- 流体生命质。
- 品质印记。
- 复杂机器 GUI。
- 静态配方赋质。

## 待确认问题

- 多个品控控制器的长期规则是否维持“选择可支付的最高档控制器”，还是改为按最近收割机、优先级或平均分配处理。
- 是否新增车载生命质接收口，把外部对接口和内部控制器分离。
- 控制器内部生命质容量第一版为 512；后续是否随校准器等级、控制器升级或注入器升级提高。
- 同一库存中多个 tier 标签同时存在时，是否永远采用最高 tier。
- `#createdelightcore:life_matter` 是否允许多个不同效率的生命质物品，还是第一版只接受单一物品。
- 生命质消耗是否按作物掉落组计，还是按掉落物数量计。
- 自动收割失败时是否返还少量生命质残渣。
- 最高级校准器是否允许突破“作物地块品质 + 1”的限制。
- 是否需要为不同作物类型配置不同生命质消耗。
