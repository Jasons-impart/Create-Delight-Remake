# 官网反馈回复模板

> 语气：短、务实、少客套；能指向 FAQ / 频道 / 上游就指向。页面回复上限 1000 字，实际尽量一两句。
> 配套分诊说明：[feedback-handling.md](feedback-handling.md)。
> 状态：`done` / `need_info` / `wont_fix` / `pending`。

## 卡住 / GUI 只播动画（TPS）

```
一般是卡住了，请使用/forge tps 检查tps情况。如果是服务器请检查与服务器连通性。
```

状态：`need_info`  
例：`38WMJ5`

## 缺崩溃日志

```
请提供崩溃日志（logs/latest.log 与 crash-*.txt，可传 mclo.gs）。没有日志无法定位。
```

状态：`need_info`

## 信息不足（步骤 / 截图）

```
提供的信息不够，请补充：①完整操作步骤；②出现问题的截图；③相关日志。
```

状态：`need_info`

## 下版本 / 已排期修复

```
下版本修复。
```

或：

```
整合包下个版本修复。
```

状态：`done`

## 升级到最新版

```
请先升级到最新正式版复测；若仍复现，请附日志与步骤。
```

状态：`need_info`（几乎确定已修可用 `done`：「最新版本已修复，请升级。」）

## 已修复 / 疑似已修

```
最新版本应该已经解决，请升级后复测。
```

状态：`done`

## Quality Food 存档序列化 NPE（LevelData.serializeNBT）

识别：崩溃堆栈含 `de.cadentem.quality_food.capability.LevelData.serializeNBT`（存档保存时 NPE）。例：`UUWFHY`、`XPP39S`（及同栈如 `BQ33WQ`）。

已在整合包 **v0.5.0.16** 修复（HotAI PR #2458：`LevelData.badiff` / `BlockData.badiff`）。**v0.5.0.15 及更早**出现本堆栈时：

```
最新版本 v0.5.0.16 已修复 Quality Food 存档保存时空指针崩溃，请升级后复测。临时解决方案可参考 https://pd.qq.com/s/3fzphb0w
```

状态：`done`

**必附临时方案链接**（教训：`UUWFHY` / `XPP39S`）：本堆栈回复须同时含升级说明与上述临时方案链接，不可只写「请升级」。

若同时确认有自加模组：先套「用户自行增删 / 升级模组」规则（点名多余模组，状态多为 `wont_fix`）；若仍附带本技术说明，在技术段前加「下面的解答不保证正确性」，再写升级 + 临时方案链接。

```

状态：`done`

```

状态：`done`

## 用户自行增删 / 升级模组

```
制作组没有能力解决用户自己增加模组的问题，可在频道与社区其他热心玩家讨论。
```

状态：`wont_fix`

## 存档跨版本 / 自升模组

```
1. 存档不建议跨小版本迁移（0.x.y.z 的 y），我们无法保证兼容性。
2. 不要自己升级模组，我们无法保证升级后的兼容性。
3. 请在全新存档且不升级模组的情况下测试，若仍有同样问题再反馈。
```

状态：`wont_fix`（官方包新档仍有问题则改 `need_info`）

### 特例：0.4.8 → 0.5.0 且末地相关

在已套用上面三条、状态仍为 `wont_fix` 的前提下，**仅当**玩家是从 **0.4.8 升到 0.5.0**、且问题明确与**末地**相关时，可在三条后**追加**社区参考（非官方支持）。先写明：这是社区友情提供的参考方案，**官方并不建议跨版本升级**；需要用到 mcaselector。

可追加：

```
（补充）以下为社区友情提供的参考方案，非官方支持；官方并不建议跨版本升级。0.4.8 升 0.5 末地相关可参考（需 mcaselector）：https://pd.qq.com/s/4opq6bmen?b=2
```

其他跨 y 位迁档、非末地、或非 0.4.8→0.5.0 路径：只回上面三条，不附此链接。
