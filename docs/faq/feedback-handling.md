# 官网问题反馈：分诊与回复经验

> 面向制作组处理 [官网反馈页](https://www.xn--dctt54dhmrbwo.com/feedback.html) 时使用。玩家可读的机制说明仍以 [CDR-FAQ.md](CDR-FAQ.md) 为准。
>
> 语料：官网反馈库（约 764 条，统计日 2026-10-15）+ 人工打样。短回复模板见 [feedback-reply-templates.md](feedback-reply-templates.md)。
>
> **流程**：自动/助手分诊并拟回复 → **人工审核通过后再发布**；需要改任务、魔改或复现时转 MC 开发，未确认前不写死具体版本号（已有共识可用「下版本修复」）。

## 状态怎么选

| 状态 | 页面文案 | 何时用 |
|---|---|---|
| `pending` | 未处理 | 还在查、等开发核对，或已回复但结论未定 |
| `done` | 已完成 | 已给明确结论：已修 / 下版本修 / 操作建议足够自助 |
| `need_info` | 缺信息 | 缺日志、步骤、截图、版本或单/多人信息，无法继续 |
| `wont_fix` | 不必解决 | 上游模组、用户自改包、设计不做、已知平台限制 |

### 经验法则

1. **先看版本、是否改包**：过旧版本先让升级；自行增删/升级模组 → 基本 `wont_fix`，要求官方包 + 新档复测。
2. **崩溃无日志 → 只回要日志**，不要猜根因。
3. **能一句话说清就一句话**；需要步骤时用短编号列表。命令写成可复制形式（如 `/forge tps`）。
4. **包内能修**（任务书错字、魔改配方、已有 PR）→ `done`；**只能上游修** → `wont_fix` 并点名模组。
5. **存档跨 `y` 位版本迁移**默认不保证 → `wont_fix` + 三条警告（见模板）。特例：`0.4.8→0.5.0` 且末地相关时，可在三条后追加社区参考链接（需声明非官方支持、官方不建议跨版本升级；见模板）。
6. **界面卡住、只播动画打不开 GUI**：先怀疑 TPS / 服务端卡顿或联机连通性，引导 `/forge tps`（服务器再查连通性），并标 `need_info` 等玩家回报；例：`38WMJ5`。
7. **Quality Food `LevelData.serializeNBT` NPE**（v0.5.0.15 及更早）：已修于 v0.5.0.16；回复须含升级 + 临时方案链接（见模板），状态 `done`。
8. **请求兼容/加入额外模组**（GitHub 或官网）：明确写「制作组暂时没有计划支持」；短、非技术。崩溃因自加模组时，先点名不兼容并建议移除，**勿**写 mixin/类名等内部诊断（见模板）。

## 分诊顺序

1. 读现象 + 整合包版本 + 是否改包 + 有无附件/日志。
2. 归入下一节某一主题，套用对应短模板。
3. 拟回复送审；通过后再 `POST /api/feedback/reply`，并按上表改状态。
4. 卡住（任务配置、代码定位、需复现）→ 转 MC 开发，不在未确认时承诺修复版本。

## 常见主题与处置

### 崩溃 / 缺日志

- **现象**：打开就崩、闪退、Ticking player、卡死；只有「闪退」无附件。
- **处置**：无日志一律要 `latest.log` / `crash-*.txt`（可用 mclo.gs）。有日志再判包内 bug、上游 mod、用户改包。
- **状态**：缺日志 → `need_info`；已定位且下版本修 → `done`。

### 卡住 / GUI 只播动画

- **现象**：原版箱子、背包等界面打不开，仅播放动画；部分模组容器仍正常。
- **处置**：优先排查 TPS / 卡服 / 联机连通性（`/forge tps`）；再视情况要日志与是否仅特定维度/结构。
- **状态**：先给检查步骤 → `need_info`。

### 已修复 / 下版本修复

- **现象**：旧版已知问题、测试版已修、模组已移除。
- **处置**：「升级到最新」或「下版本修复」；可附 GitHub PR 号。
- **状态**：`done`。

### Quality Food 存档序列化 NPE（LevelData.serializeNBT）

- **现象**（内部识别）：存档保存 / server tick 崩溃；堆栈含 `quality_food` 的 `LevelData.serializeNBT`（`Quality.ordinal()` 因 `HashMap.get` 为 null）。例：`UUWFHY`、`XPP39S`。
- **处置**：已修于整合包 **v0.5.0.16**（HotAI PR #2458）。对 **v0.5.0.15 及更早** 同栈反馈：`done`，套用模板对外句「最新版本已修复这个问题，请升级后复测。临时解决方案可参考 https://pd.qq.com/s/3fzphb0w」。**临时方案链接必须附上**（不可只写升级）。
- **对外**：勿抛玩家无概念的技术细节（类名/空指针等）；要么先用人话说明再提，要么略过。
- **叠加改包**：先按自改包规则点名多余模组（多为 `wont_fix`）；若仍附技术说明，技术段前加「下面的解答不保证正确性」，再写升级 + 临时方案。
- **状态**：官方包同栈 → `done`；改包且只给改包结论 → `wont_fix`。

### 机制说明 / 指向 FAQ

- **现象**：不会用 JEI/思索、过滤器、作物光照、快捷键等。
- **处置**：短答 + 指向 [CDR-FAQ.md](CDR-FAQ.md) 或思索；能一句话答完就不要长文。
- **状态**：已给正确做法 → `done`。

### 任务书 / 进度

- **现象**：目标写错、进度不解锁、Quest locked、章节缺失。
- **处置**：确认配错 → `done`（下版本修）；需核对配置可保持 `pending` 并转开发。
- **状态**：明确错漏 → `done`；机制无法改 → `wont_fix`。

### 配方 / 平衡建议

- **现象**：成功率低、缺配方、指向错误机器。
- **处置**：明显配错 → `done`；纯数值偏好 → `wont_fix` 或「后续考虑」。

### AE × 机械动力等兼容

- **现象**：存储总线吞物、保险柜循环卡死等。
- **处置**：确认上游兼容则转作者；包内可绕过则给操作建议。
- **状态**：上游 → `wont_fix`；包内可修 → `done`。

### 联机 / 服务器 / 网络

- **现象**：超时、秒退、混合端、假玩家炸服。
- **处置**：区分网络与崩溃；要双端日志；已知频道置顶可甩链接。
- **状态**：纯环境建议 → `done`；缺日志 → `need_info`。

### 安装 / 下载 / 启动器

- **现象**：客户端很小、模组下载失败、安装超时。
- **处置**：换网络/加速器、HMCL/PCL 官方源；确认官网 Client 包。玩家侧细节见 FAQ「进入游戏前」。
- **状态**：可操作建议 → `done`。

### JDK / JVM

- **现象**：挂机闪退、GC 崩溃、过高 Java 版本。
- **处置**：整合包推荐 **JDK17**。
- **状态**：明确 JDK 问题 → `done`；无日志 → `need_info`。

### 用户自改包 / 跨版本存档

- **现象**：自增模组、自升模组、跨 `y` 位迁档后异常（含 `0.4→0.5` 等）。
- **处置**：声明制作组不保证；套用模板三条警告；要求官方包 + 新档复测；引导频道讨论。
- **特例**：`0.4.8→0.5.0` 且问题为**末地**相关时，可在三条后追加社区参考（需 mcaselector）：<https://pd.qq.com/s/4opq6bmen?b=2>。必须写明：仅为社区友情提供的参考方案，**非官方支持**，官方**不建议**跨版本升级。其他跨版本路径不附此链接。
- **状态**：基本 `wont_fix`（官方包新档仍复现再改 `need_info`）。

### 请求兼容 / 加入额外模组

- **现象**：希望整合包官方支持某附加模组（如森罗物语：厨房）；或自加后崩溃并隐含「请做兼容」。
- **处置**：短回复明确 **暂时没有计划支持**；若已崩溃，点名该模组不兼容并建议先移除。官网回复保持短、非技术；内部诊断（mixin、类名、堆栈细节等）只留内部/补丁讨论，**不要**写进对玩家回复。
- **状态**：`wont_fix`。
- **例**：GitHub `#2489`。

### 上游模组 / 设计不做

- **现象**：需模组作者修；或与调性不符、工作量过大的建议。
- **处置**：点名模组或说明不做原因；能给替代更好。
- **状态**：`wont_fix`。

## 与玩家 FAQ 的衔接

- 安装、路径、PCL 镜像、JDK、光影、过滤器等 → 优先「见 FAQ」，避免在回复里复制长文。
- 玩家如何提交反馈 → 见 [CDR-FAQ.md](CDR-FAQ.md)「还有其他问题要反馈？」；官网入口：<https://www.xn--dctt54dhmrbwo.com/feedback.html>。
- 本文件只记 **分诊与话术**；玩法事实以 FAQ 与仓库实现为准，随人工打样持续修订。

## 管理接口备忘（同域）

- 公开列表：`GET /api/feedback/records`
- 令牌校验：`GET /api/feedback/list` + `Authorization: Bearer <管理令牌>`
- 改状态：`PUT /api/feedback/status`，body `{ "id", "status" }`
- 回复：`POST /api/feedback/reply`，body `{ "id", "text" }`（最多 1000 字）
- 删除：`DELETE /api/feedback/delete?id=`（慎用，附图一并删除）
