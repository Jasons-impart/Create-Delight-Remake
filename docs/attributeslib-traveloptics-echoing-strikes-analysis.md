# AttributesLib、暗影瘴气与回响打击伤害联动研究

日期：2026-07-21

状态：本地 JAR 与公开上游源码调研完成，尚未实施修复

## 研究结论

当前 CDR 的极端暴击伤害不是单一模组独立造成的，而是三套机制串联后的结果：

```text
Travel Optics 暗影瘴气
把最终法术强度直接转换为高等级“深渊打击”
        ↓
深渊打击同时线性提高 AttributesLib 暴击率与暴击伤害
        ↓
AttributesLib 1.3.7 对超额暴击进行递减后的多重乘算
        ↓
Iron's Spells 回响打击记录已经被增伤的 LivingHurtEvent 金额
        ↓
回响作为玩家造成的独立法术伤害再次进入暴击和其他增伤管线
```

其中最危险的两个放大点是：

1. AttributesLib 1.3.7 的多重暴击层数之间采用乘算，而不是上游新版本使用的加算。
2. 回响打击在默认事件优先级读取已经修改过的伤害，回响自身又可能再次获得同一类增伤，形成暴击或通用增伤的二次取样。

因此，仅削弱暗影瘴气、仅封顶暴击率或仅禁止回响暴击，都只能处理其中一部分问题。更完整的方向是同时回移上游加算公式，并让回响基于进入模组增伤管线前的伤害快照生成。

## AttributesLib 1.3.7 的暴击属性

### 注册范围

`attributeslib:crit_chance`：

- 默认值：`0.05`，即 5%。
- 最小值：`0`。
- 注册最大值：`10`，即 1000%。

`attributeslib:crit_damage`：

- 默认值：`1.5`，即 150%伤害倍率。
- 最小值：`1`。
- 注册最大值：`100`。

CDR 虽然安装了 AttributeFix，但当前 `config/attributefix.json` 中这两个属性均为 `enabled: false`：

```text
attributeslib:crit_chance  最大值仍为 10
attributeslib:crit_damage  最大值仍为 100
```

因此，在当前配置下，即使某个效果或界面累计出5000%暴击率，`getAttributeValue` 正常读取到的有效暴击率仍应被 `RangedAttribute` 限制在1000%。如果未来启用 AttributeFix 对这两个属性的覆盖，必须重新评估所有极端数值。

### 1.3.7 多重暴击算法

旧版实现可概括为：

```java
float critMult = 1.0F;

while (random.nextFloat() <= critChance && critDamage > 1.0F) {
    critChance--;
    critMult *= critDamage;
    critDamage *= 0.85F;
}

damage *= critMult;
```

含义如下：

- 每100%暴击率保证一重暴击。
- 不足100%的剩余部分决定下一重暴击概率。
- 每一重使用一次新的随机判定。
- 每成功一重，剩余暴击率减去100%。
- 下一重暴击伤害衰减为上一重的85%。
- 当下一重暴击伤害不高于 `1×` 时停止。
- 所有成功层数互相乘算。

若初始暴击率为 `C`、暴击伤害为 `D`，第 `k` 重使用的倍率为：

```text
D × 0.85^(k-1)
```

连续触发 `n` 重时，旧版总暴击倍率为：

```text
D^n × 0.85^[n(n-1)/2]
```

这使暴击伤害同时影响每层倍率和可继续触发的有效层数，容易形成近似指数增长。

### 上游新版本的加算公式

上游在2025-05-10提交 `Make multicrit additive`，保留多重暴击与每层15%衰减，但将层与层之间改为加算：

```java
float damage = originalDamage;

while (random.nextFloat() <= critChance && critDamage > 1.0F) {
    critChance--;
    damage += originalDamage * (critDamage - 1);
    critDamage *= 0.85F;
}
```

连续触发 `n` 重时，新版总倍率为：

```text
1 + Σ[D × 0.85^k - 1]，k = 0 ... n-1
```

新版仍保留超额暴击率的价值，但避免层与层之间继续相乘。

### 数值对比

以下结果不包含目标抗性、护甲、其他增伤或原版跳劈，只比较多重暴击算法。

#### 400%暴击率、300%暴击伤害

四重倍率依次为：

```text
3.0 → 2.55 → 2.1675 → 1.842375
```

| 算法 | 总倍率 |
|---|---:|
| 1.3.7 乘算 | `30.5491×` |
| 上游新版加算 | `6.559875×` |

#### 显示5000%暴击率、300%暴击伤害

当前配置下有效暴击率按1000%计算。300%暴击伤害衰减至第七重后，下一重为 `0.9617×`，即使解除暴击率上限也不会继续。

```text
3.0000 → 2.5500 → 2.1675 → 1.8424
→ 1.5660 → 1.3311 → 1.1314
```

| 算法 | 总倍率 |
|---|---:|
| 1.3.7 乘算 | `72.0520×` |
| 上游新版加算 | `7.58846×` |
| 旧版/新版 | 约 `9.5` 倍 |

#### 显示5000%暴击率、400%暴击伤害

当前配置下有效暴击率仍按1000%计算。400%暴击伤害可维持九个高于 `1×` 的有效层数：

```text
4.0000 → 3.4000 → 2.8900 → 2.4565 → 2.0880
→ 1.7748 → 1.5086 → 1.2823 → 1.0900
```

| 算法 | 总倍率 |
|---|---:|
| 1.3.7 乘算 | `754.434×` |
| 上游新版加算 | `12.4902×` |
| 旧版/新版 | 约 `60.4` 倍 |

### 原版跳劈的额外关系

`AttributeEvents.vanillaCritDmg` 会在攻击满足原版暴击条件时，将原版暴击倍率设置为原倍率与 `crit_damage` 中的较大值。随后 `LivingHurtEvent` 上的 AttributesLib 随机暴击仍会继续处理。

因此，原版跳劈与 AttributesLib 随机多重暴击是两个阶段，极端构筑下可能继续叠加。实际设计和测试时必须区分：

- 原版 `CriticalHitEvent` 的跳劈倍率。
- `LivingHurtEvent` 的 AttributesLib 随机多重暴击倍率。

## 社区反应、配置与现成补丁

### 社区和上游反应

官方公开 issue 中没有找到专门针对“1.20.1 超额暴击乘算指数膨胀”的集中讨论，但上游作者后来直接提交了加算修改。这说明后续版本已实际处理多重暴击乘算风险，只是没有回移到1.20.1分支。

公开 issue 中能找到的相关讨论主要是：

- 主手与副手暴击属性叠加属于 Minecraft 属性系统行为。
- 新版增加 `apothic_attributes:cannot_critically_strike` 伤害类型标签，用于阻止特定伤害暴击。

该伤害类型标签属于后续新版能力，CDR 当前1.20.1 / 1.3.7实现中不存在。

### 原模组配置能力

当前 `config/attributeslib.cfg` 只开放：

- 属性界面开关。
- 药水提示开关。
- 隐藏属性列表。
- 护甲减伤公式。
- 保护附魔减伤公式。

它没有开放：

- 暴击率上限。
- 多重暴击开关。
- 乘算/加算模式。
- 每层15%衰减。
- 最大暴击层数。
- 最终暴击倍率上限。

AttributesLib 使用 MIT 许可证，可以从源码分支回移修改，但直接维护修改版原 JAR 不利于 Packwiz 和升级。更适合 CDR 的方式是独立兼容模组或已有核心模组中的窄范围 Mixin。

## 暗影瘴气为何放大暴击属性

### 法术本身的处理

Travel Optics 的 `ShadowedMiasmaSpell`：

- 最大法术等级：3。
- 基础法术强度：2。
- 每级增加法术强度：1。
- 三级时未乘属性的基础强度为4。
- 持续时间为 `190 + 法术等级 × 150` tick。
- 施法时对附近敌人施加灾变的深渊诅咒，并对施法者施加 Travel Optics 的深渊打击。

Iron's Spells 的通用 `getSpellPower` 公式为：

```text
最终法术强度 =
[基础强度 + 每级强度 × (法术等级 - 1)]
× 通用法术强度
× 学派法术强度
× 法术配置倍率
```

暗影瘴气将该结果直接转为整数，并用 `最终法术强度 - 1` 作为深渊打击的效果放大器。药水效果属性修饰符又按 `放大器 + 1` 计算，因此深渊打击的实际等级正好等于取整后的最终法术强度。

### 深渊打击提供的属性

`AbyssalStrikeEffect` 每一级固定提供：

```text
+6% 暴击率
+1.5% 暴击伤害
```

若深渊打击等级为 `S`：

```text
额外暴击率   = 0.06 × S
额外暴击伤害 = 0.015 × S
```

例如最终法术强度为200：

```text
额外暴击率   = 1200%
额外暴击伤害 = 300%
```

加上 AttributesLib 默认150%暴击伤害，总暴击伤害约为450%。暴击率在当前 AttributeFix 配置下会被限制为1000%，但暴击伤害仍可继续提高，并延长旧版乘算中有效多重暴击的层数。

如果某个来源或界面累计显示约5000%暴击率，对应深渊打击等级大约为833，同时会带来约1250%额外暴击伤害。此时总暴击伤害接近1400%，即使有效暴击率只允许十个保证层数，旧版乘算仍可达到上亿级倍率。

### 为什么这更像跨模组失衡

暗影瘴气的公开法术说明只提到深渊诅咒和扩散效果，没有展示：

- 深渊打击会提高 AttributesLib 暴击率与暴击伤害。
- 最终法术强度会直接成为深渊打击等级。
- 通用法术强度与邪术法术强度先乘算，再转为效果等级。
- 暴击属性进入 AttributesLib 1.3.7 后会触发多重乘算。

这更像 Travel Optics 的线性效果等级设计与 AttributesLib 旧版乘算公式之间的跨模组失衡，而不是暗影瘴气有意设计为天文数字伤害。

## 铁魔法回响打击为何进一步放大伤害

### 基础机制

Iron's Spells 原装回响打击：

1. 给施法者施加 `Echoing Strikes` 效果。
2. 施法者造成非 `SpellDamageSource` 的攻击时，在 `LivingHurtEvent` 中创建回响实体。
3. 回响实体记录当时的 `event.getAmount()`。
4. 20 tick 后在半径2格内造成末影法术伤害。
5. 回响伤害使用距离衰减，中心区域最高100%，边缘最低约40%。
6. 回响伤害本身是 `SpellDamageSource`，不会继续生成下一次回响，因此不存在无限递归。

回响基础比例为：

```text
回响比例 = (法术等级 + 2) × 10% × 施法者最终法术强度倍率
```

在最终法术强度倍率为 `1` 时：

| 法术等级 | 回响比例 |
|---|---:|
| 1 | 30% |
| 2 | 40% |
| 3 | 50% |
| 4 | 60% |
| 5 | 70% |

该比例还会乘以通用法术强度和末影法术强度，因此实际可以超过100%。

### 事件优先级导致记录暴击后伤害

AttributesLib 的 `apothCriticalStrike` 监听优先级为 `HIGH`。

Iron's Spells 的 `EchoingStrikesEffect.createEcho` 没有显式优先级，因此使用默认 `NORMAL`。

Forge 事件执行顺序使流程成为：

```text
LivingHurtEvent 初始金额
        ↓
AttributesLib HIGH：修改为多重暴击后的金额
        ↓
Iron's Spells NORMAL：读取已经修改的 event.getAmount()
```

回响记录的不是未处理攻击伤害，而是已经包含 AttributesLib 暴击以及其他更高优先级修改的金额。

### 回响自身为何还能暴击

回响爆炸创建 `SpellDamageSource` 时：

- 直接伤害实体是回响实体。
- 真正攻击者/伤害归属者仍是玩家。

AttributesLib 1.3.7 的暴击处理只检查伤害归属者是否为 `LivingEntity`，没有排除魔法伤害或 `SpellDamageSource`。因此回响爆炸会再次读取玩家的 `crit_chance` 与 `crit_damage`，重新进行一次完整多重暴击。

Iron's Spells 只阻止 `SpellDamageSource` 再创建新的回响，没有阻止其他模组继续放大这次法术伤害。

### 暴击倍率平方

设：

- `B` 为进入 AttributesLib 前的攻击伤害。
- `C` 为一次 AttributesLib 多重暴击总倍率。
- `E` 为回响比例和距离衰减后的系数。

当前流程近似为：

```text
原攻击 = B × C
回响记录 = B × C
回响再次暴击 = B × C × E × C
总伤害 = B × C + B × E × C²
```

例如旧版400%暴击伤害的保证多重暴击倍率约为 `754.434×`，五级回响按中心默认70%计算：

```text
原攻击 ≈ B × 754.434
回响   ≈ B × 0.7 × 754.434²
       ≈ B × 398,400
```

此例尚未加入回响比例继续受到法术强度放大、目标末影抗性、其他攻击者增伤或目标易伤的影响。

## 问题不只存在于暴击

仅禁止回响触发 AttributesLib 暴击，只能修复一条已知联动。任何在回响记录前修改原攻击、并且又能作用于回响法术伤害的机制，都可能被二次取样。

设若干事件型增伤的合并倍率为 `M`：

```text
原攻击 = B × M
回响记录 = B × M
回响重新进入伤害管线后再次获得 M
回响伤害 = B × E × M²
```

可能参与的来源包括：

- AttributesLib 暴击。
- 攻击者通用增伤。
- 目标易伤。
- 血量条件增伤。
- 背刺、处决或连击增伤。
- 其他监听 `LivingHurtEvent` 的模组机制。

并非所有增伤都会对魔法回响再次适用，但依赖逐个模组列黑名单无法从根本上保证兼容。

## Fallen 宝石强度与重复宝石的叠加边界

Fallen Gems & Affixes 的宝石强度本身是线性缩放器，而不是额外的指数层。其处理可以概括为：

```text
总宝石强度 P = 1 + 各 IGemPowerProvider 提供值之和
最终再乘催化插槽提供的宝石强度倍率

单颗宝石的原始数值 x → x × P
```

因此，宝石增幅、汇流、恶意、创生等强化提高的是每颗宝石写入属性修饰符的数值；它们不会仅因“宝石强度”这一机制自动把多颗宝石变成指数增长。重复镶嵌后的最终叠加仍由宝石 JSON 中的 `operation` 决定。

设同一种宝石镶嵌 `m` 颗，每颗原始比例为 `x`，总宝石强度为 `P`：

| operation | 重复宝石的典型结果 | 备注 |
|---|---|---|
| `ADDITION` | 增加 `m × x × P` 个属性点 | 适用于固定数值或暴击率等百分点属性。 |
| `MULTIPLY_BASE` | 相对基础值增加 `m × x × P` | 多颗同类宝石的比例贡献线性相加。 |
| `MULTIPLY_TOTAL` | 每颗分别形成 `1 + x × P` 的最终乘数 | 多颗之间仍按 Minecraft 最终乘算规则组合。 |

需要特别避免把每颗宝石的基础 `1` 重复计入加算公式。对于线性比例叠加，`m` 颗同值宝石应理解为：

```text
1 + m × x × P
```

而不是把完整的 `1 + x × P` 当作可重复相加的属性增量。

这项修正意味着：Fallen 宝石强度不必因公式本身被全面移除，但当前宝石数值仍需要重新平衡。词缀通常不能在一件装备上重复同一个 ID，而同种宝石可以占据多个插槽；当整合包提供较多插槽和较高宝石强度时，原本按少量插槽设计的单颗数值仍可能过高。

建议采用以下边界：

- 可重复镶嵌的通用增伤宝石，其单颗数值应明显低于同类不可重复词缀。
- `MULTIPLY_TOTAL` 宝石按“填满可用插槽”的最坏组合审核，必要时降低单颗数值或改为 `MULTIPLY_BASE`。
- 暴击率、暴击伤害、吸血、闪避和护甲穿透等百分点属性优先使用 `ADDITION`，并单独控制单颗值和总上限。
- Fallen 的宝石增幅、汇流、恶意、创生与催化插槽可以保留构筑特色，但应设置总宝石强度上限，避免与大量插槽共同放大。
- 调整应覆盖 Apotheosis 与 Fallen Gems & Affixes 两套宝石数据，优先修改具体异常宝石，不机械替换全部 operation。

## 修复方向比较

### 方案一：只禁止回响暴击

做法：识别 `SpellDamageSource.spell() == ECHOING_STRIKES_SPELL`，让 AttributesLib 跳过该伤害。

优点：

- 修改范围小。
- 保留回响复制原攻击最终金额的语义。
- 能直接消除已确认的 AttributesLib 暴击平方。

缺点：

- 其他模组的事件型增伤仍可能重复结算。
- 1.20.1 没有新版 `cannot_critically_strike` 标签，需要代码特判。
- 只能解决已知模组，跨模组扩展性差。

结论：适合作为临时止血，不适合作为唯一长期方案。

### 方案二：让回响记录增伤管线前的伤害快照

做法：在 `LivingHurtEvent` 被外部监听器修改前保存初始金额，回响使用该快照乘以回响比例，而不是读取 NORMAL 阶段已经变化的 `event.getAmount()`。

新流程：

```text
保存初始金额 B
        ↓
原攻击正常经过模组增伤，造成 B × M
        ↓
回响以 B × E 为基础生成
        ↓
回响作为独立伤害正常经过一次增伤管线，造成 B × E × M
```

总伤害变为：

```text
B × M × (1 + E)
```

优点：

- 从机制上避免任意事件型增伤被回响复制后再次结算。
- 原攻击和回响各自只通过一次增伤管线。
- 不依赖逐个识别 AttributesLib、OED 或未来加入的增伤模组。

缺点：

- 必须定义“初始金额”的准确阶段。
- 单纯改为 `EventPriority.HIGHEST` 仍可能受到其他 `HIGHEST` 监听器注册顺序影响。
- 回响不再严格复制最终实际伤害，而是复制进入模组事件增伤前的攻击快照。

建议定义：

> 原始伤害是 `LivingHurtEvent` 刚创建、尚未被 Forge 事件监听器修改时的金额。

该金额通常已经包含攻击冷却、原版跳劈、原版附魔和攻击生成阶段的计算，但不包含大多数 `LivingHurtEvent` 增伤。实现上可先用独立监听器的 `HIGHEST` 优先级验证，再考虑在 Forge 伤害钩子入口或事件构造位置保存不可变快照，消除同优先级顺序不确定性。

结论：这是处理未知模组增伤重复结算的推荐长期方案。

### 方案三：回移上游加算多重暴击

做法：用窄范围 Mixin 将1.3.7的层间乘算替换为上游新版加算。

优点：

- 与官方后续实现一致。
- 保留超额暴击率、多重暴击和15%递减特色。
- 普通攻击、回响和其他伤害源都会一起摆脱指数乘算。

缺点：

- 不能单独解决回响复制所有事件型增伤的问题。
- 需要独立兼容模组或核心源码维护。

结论：应与方案二组合，而不是相互替代。

### 方案四：限制暗影瘴气的深渊打击等级

可选做法：

- 为深渊打击等级设置硬上限。
- 不再把最终法术强度直接作为效果等级。
- 使用平方根、对数或分段公式转换法术强度。
- 将每级 `+6%/+1.5%` 改为可配置或递减收益。

优点：直接控制主要暴击属性来源。

缺点：只处理 Travel Optics，无法修复其他来源的高暴击和回响二次取样。

结论：属于平衡层调整，应在通用伤害机制修正之后再决定。

## 推荐组合

建议按以下顺序推进：

1. 回移上游加算多重暴击，先消除 AttributesLib 1.3.7 的指数乘算。
2. 为回响打击记录不可变的初始伤害快照，避免所有事件型增伤平方。
3. 保留 Iron's Spells 已有的 `SpellDamageSource` 递归保护，确保回响不会生成回响。
4. 让回响作为独立末影法术伤害正常经过一次抗性、距离衰减和增伤管线。
5. 再评估暗影瘴气是否需要深渊打击等级上限或非线性转换。
6. 如需更强可调性，为兼容模组提供多重暴击模式、衰减、最大层数、最终倍率和深渊打击等级上限配置。

目标模型应当是：

```text
每个伤害实例只经过一次通用增伤管线
        +
超额暴击保留价值但不进行层间乘算
        +
回响是独立二段伤害，不是最终伤害倍率的平方器
```

## 实施后的验证清单

### AttributesLib

- 50%、100%、150%、250%暴击率的层数和概率符合预期。

- 原版跳劈与 AttributesLib 随机暴击的阶段关系有明确测试结果。
- AttributeFix 对 `crit_chance` 和 `crit_damage` 仍保持预期配置。

### 暗影瘴气

- 三级法术的基础强度为4。
- 通用法术强度与邪术法术强度对深渊打击等级的实际乘算符合公式。

- 高法术强度下暴击属性不会出现无法解释的截断或溢出。

- 一级至五级在默认法术强度下分别记录30%至70%的回响比例。

- 回响不会递归生成新回响。
- 原攻击和回响各自只获得一次 AttributesLib 暴击或其他通用增伤。
- 回响仍正常受到末影法术抗性和目标侧防御处理。
- 多目标范围回响不会因快照复用而串用其他目标的伤害数据。
