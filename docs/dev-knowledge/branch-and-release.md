# 版本号、小版本阶段与分支角色

本文说明齿轮盛宴（Create-Delight-Remake）的**版本号含义**、**小版本产品阶段**，以及 `main` / `release-vxxxx` 的高层角色。发布操作步骤见 `.agents/skills/release/SKILL.md`；人工入口见 [development.md](../development.md#版本发布流程)。

> 本页面向维护分支读者（如 `release-v050x`），只记版本方案与阶段；不展开具体模组补丁出包约束。

## 版本号含义

当前版本号格式：

```text
v0.{大版本}.{小版本}.{修订号}
```

示例：`v0.5.0.16` → 大版本 `5`、小版本 `0`、修订号 `16`。同一「小版本线」写作 `0.5.0.x`。

发布脚本（`release-plan.ps1`）按四段 `vA.B.C.D` 解析；其中 `A.B.C`（如 `0.5.0`）对应一条小版本线，并推导维护分支名 `release-v$A$B$C`x（如 `release-v050x`）。

## 更新节奏

以每个假期（寒暑假、节假日）**开始前几天**为节点，发布一个**新小版本的正式版**。自 `0.4.7.x` 起，每个小版本都按下一节的阶段推进。

## 小版本阶段（产品视角）

自 `0.4.7.x` 起，每个小版本依次经历：

| 阶段 | 做什么 | 渠道与补丁 |
|---|---|---|
| **测试版-功能更新** | 快速、频繁加功能：加/更新 mod、自创多方块、自创机制等 | 仅 GitHub；**无**更新补丁 |
| **抢先预览版-准备发布** | 正式版前的**最后一个测试版**，通常在正式版前 **2–3 周**发布。以此为分界，**之后不再做功能更新** | 仅 GitHub；**无**更新补丁 |
| **正式版** | 基于抢先预览版反馈：修 bug、调不合理数值、任务书勘误后，在假期前发布 | 正式渠道；此后维护更新带补丁 |
| **正式版-持续维护** | 下一小版本正式版发布前：稳定且易复现的崩溃、严重影响正常流程的问题、其他确有必要的更新；同一小版本下正式版存档一般可无损升级 | 每次维护更新都有补丁 |
| **正式版-停止维护** | **下一小版本正式版**发布后转入；制作组不再处理该版本 bug 反馈、不提供排查（社区频道仍可能有玩家帮忙） | — |

### 与发布工具的对应（勿硬套名称）

release skill / 脚本只有两类 GitHub Release：**正式**（非 prerelease）与 **测试**（prerelease，tag 常带 `-test`）。仓库**没有**单独的「抢先预览」Release 类型或脚本开关。

- **测试版-功能更新**、**抢先预览版**：都是产品阶段；发布时通常仍走「测试 / prerelease」。抢先预览 = 正式版前最后一个测试包这一产品节点，不是第三种 `ReleaseType`。
- **正式版** 及之后的 **持续维护** 更新：走「正式 / 非 prerelease」Release。
- 测试与抢先预览「无更新补丁」与脚本行为一致：测试版 Release 说明写明不提供 Patch，需下完整包。

## 分支角色（高层）

| 分支 | 角色 |
|---|---|
| `main` | 主要开发分支；持续合入功能与修复 |
| `release-vxxxx` | 某一小版本正式稳定线的维护分支（如 `release-v050x` 对应 `0.5.0.x`） |

命名与 `release-plan.ps1` 一致：未指定 `-TargetBranch` 时推导 `release-v$A$B$C`x；分支存在则用之，否则回退 `main`。历史例：`release-v045x` … `release-v048x`、`release-v050x`。

常见对应（不必钉死唯一分支）：

1. **测试版-功能更新**：主要在 `main` 上快速合入功能。
2. **抢先预览前后**：常切出或落在 `release-vxxxx`；以抢先预览为分界后不再功能更新。
3. **正式版 → 正式版-持续维护**：该 `release-vxxxx` 上按上表范围做维护修订；下一小版本正式版发布后，本线进入**停止维护**。

## 给维护者的短约束

- 对外描述阶段时用上表产品名称；对内跑发布脚本时只用「正式 / 测试」，不要发明「抢先预览」专用 ReleaseType。
- 本页是开发与发布策略摘要，不替代玩家 FAQ。
