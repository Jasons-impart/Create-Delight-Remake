# 技术做法索引

本文件记录紧凑的“某类修改该怎么做”项目笔记；如果流程已经复杂到需要固定步骤或多条命令，应提升为 skill。

| 目标 | 编辑位置 | 检查清单 | 验证方式 | 何时提升为 skill |
|---|---|---|---|---|
| 搭建本地开发环境 | `GettingStarted.md` | 该流程面向尚未 clone 仓库的用户，必须在根文档中自包含；不要提升为项目 skill。 | 确认实例目录含 `.git/`、`kubejs/`、`config/`、`mods/*.jar`、`pack.toml` 和 HMCL 版本文件。 | 不提升；clone 前无法依赖仓库内 skill。 |
| 修改 KubeJS 配方 | `kubejs/server_scripts/{Mod}/`，helper 位于 `kubejs/server_scripts/util/` | 搜索 `.js` 配方脚本，优先使用 `remove_recipes_id`、`cutting_2`、`centrifugation` 等既有 helper，配方 id 使用 `createdelight` 命名空间。 | 游戏内执行 `/kubejs reload server_scripts`；涉及标签或掉落时再执行 `/reload`。 | 任务需要批量生成、广泛迁移或命令密集验证。 |
| 调整群系自然生物密度 | `kubejs/data/<namespace>/worldgen/biome/<biome>.json` | `weight` 只调整多个候选间的相对抽取概率，`minCount/maxCount` 控制单次成组数量；需要限制附近持续堆积时，为刷怪表中的实体添加 `spawn_costs`，提高 `charge` 或降低 `energy_budget` 会更严格。原版绯红森林没有生成势能，参考模板应使用诡异森林或灵魂沙峡谷。 | 校验每个 `spawn_costs` 实体都存在于对应 `spawners` 或已确认的模组运行时追加表；重启后在相同玩家距离、时长和群系范围内对比实体数量与间距。 | 需要跨大量群系自动生成参数或制作运行时密度统计工具。 |
| 添加集成农业鸡舍喂食项 | `kubejs/data/create_integrated_farming/chicken_food/{items,fluids}/<id>.json` | 这是集成农业自定义 datapack reload 目录，不是 KubeJS recipe；item 项用 `ingredient`（单个 `{ "item": "..." }`、`{ "tag": "..." }` 或数组）并可加 `using_converts_to`，流体项用 `fluid` 或 `tag`、`required`、`progress`、`cooldown`、`amount`，可参考 jar 内 `chicken_food/items/seeds.json` 和 `chicken_food/fluids/seed_oil.json`。 | 校验 JSON 后执行 `/reload`，日志应显示加载 item/fluid chicken food entries。 | 若需要批量同步多个动物棚或反复反编译 jar 字段，再提升为 skill。 |
| 继承 Cosmopolitan 糖浆风味 NBT | `kubejs/server_scripts/Cosmopolitan/recipe.js` | 工作台配方优先用 `e.recipes.minecraft.crafting_shaped/shapeless`，让 Cosmopolitan 的原版配方 mixin 处理 `berrySyrupFlavor`；Create 序列组装不会动态继承流体风味，需按 `berry_syrup(_spicy/_sour/_bitter/_strange)` 分别注册带 NBT 的输出。 | `/kubejs reload server_scripts` 后用不同风味输入或流体合成，确认产物保留对应 NBT。 | 多个 Cosmopolitan 风味配方需要统一迁移或补 JEI/自动化说明。 |
| 重设灾变 Boss 建筑主题 | `scripts/retheme-cataclysm-structures.py`、`scripts/cataclysm-structure-theme-map.json`、`kubejs/data/cataclysm/{structures,worldgen/structure}/` | 必须从当前 `integrated_cataclysm` JAR 读取结构基线，保留附属新增的实体、机关、拼图和方块实体；逐座对照原方块与候选方块纹理后编辑映射，不替换 `cataclysm:dungeon_block`、陷阱、容器和红石；怪物拼图池用分组内 `remove_jigsaw_pools` 精确移除，生成高度和阶段另行覆盖 `worldgen/structure` JSON；默认审计，确认后用 `--apply` 生成覆盖。 | 先运行 `--validate-only`，再对当前分组运行 `--verify-output` 做 NBT 解压字节比对；游戏内 `/reload` 后在目标维度定位新结构并检查日志、拼图实体和视觉。 | 附属结构格式、目标星球或批量视觉验收流程继续扩展时提升为 skill。 |
| 添加自定义资源或翻译 | `kubejs/assets/{namespace}/`，语言文件位于 `lang/` | 模型、贴图和语言写入所属 namespace；群系翻译键使用 `biome.{namespace}.xxx`；CD 自定义资源优先放在 `createdelight`。 | 根据资源类型执行资源重载或重启游戏；语言文件由 schema 校验。 | 资源生成或本地化流程开始重复出现。 |
| 互转 Create 与 LDLib 连接纹理 | `scripts/convert-create-ldlib-ct.py`、[格式与限制说明](../create-ldlib-connected-texture-conversion.md) | 仅处理 Create `OMNIDIRECTIONAL`；LDLib 转 Create 可无损展开，Create 转 LDLib 必须检查 47 个有效状态，默认拒绝有损结果；写 metadata 时优先让脚本合并 `.png.mcmeta`。 | 先用 `--check-only`，正式输出后检查脚本的 47 状态报告和 `LDLib → Create → LDLib` 像素 round-trip；MBD2 动态 `json_model` 需按专项方案在外层委托后做条件式 CTM rebake。 | 需要支持其他 CTType、动画图集或把 MBD2 补丁固化成重复流程时提升为 skill。 |
| 让 MBD2 总线或仓口继承控制器机壳 | [自适应机壳与连接纹理方案](../plan/mbd2-adaptive-casing-and-connected-texture-plan.md)，资源位于 `ldlib/assets/mbd2/`，Java 兼容层位于 CDC 的 `compat/mbd2/` 与 `mixin/mbd2/` | 有限材质 MVP 使用同一 `.sm` 的多状态，并在控制器 `onRecipeStatusChanged` 最后调用 `part.setMachineState(...)`；关闭 `canShare`。通用方案接通 `getPartAppearance(...)`、建立控制器到机壳 `BlockState` 的映射，并由自适应 renderer 在替换机壳区域后统一计算 CTM。 | 验证三种机壳、配方状态切换、结构失效与重载、跨总线 CTM、不同实例缓存隔离；没有 LDLib metadata 的模型不得受影响。 | 自适应 renderer、appearance 桥接和 CTM mixin 形成稳定实现与回归命令后提升为 skill。 |
| 添加游戏内 Tips | `kubejs/assets/createdelight/tips/<id>.json`、`kubejs/assets/createdelight/lang/zh_cn.json`、`config/tips.json` | 由 Tips 模组（mod id `tipsmod`）从 `assets/<namespace>/tips/*.json` 加载提示；CD 自定义提示新建 JSON，内容用 `{"tip":{"translate":"createdelight.tip.<id>"}}` 指向语言键，并在 `zh_cn.json` 添加同名翻译，避免把 `createdelight` 加入 `ignoredNamespaces`。 | 校验 tips JSON 和语言 JSON；进游戏等待 tips 轮播或重载资源后查看。 | 需要批量生成、多语言同步或定制 Tips 过滤规则。 |
| 维护 GitHub Pages 首页 | `index.html`、`docs/*.html`、`docs/*-data.js`、`.gitignore`、`.github/workflows/release.yml` | Pages 源配置为 `main` 分支根目录；根目录默认被 `.gitignore` 的 `/*` 忽略，新增根页面文件必须加 `!/<file>` allowlist；放在 `docs/` 下的 Pages 内容默认可跟踪且现有发布流程会删除 `docs/`；`docs/mods-data.js` 刷新成本高，只能在用户明确要求时手动更新。 | 合并到 `main` 后检查 `https://jasons-impart.github.io/Create-Delight-Remake/`；badge 使用完整 shields.io URL，避免 README/Jekyll 渲染差异；确认 Pages 专用文件未进入服务端包或补丁包；模组分类数据需标注截止 tag。 | 需要自动构建多页站点、发布生成目录或引入主题时再提升。 |
| 添加或更新整合包资产 | `mods/`、`resourcepacks/`、`shaderpacks/`、`packwiz-files/` | 使用 `/packwiz-assets` skill；除修复生成结果外，不手写 Packwiz 元数据。 | 运行 `scripts/sync-packwiz-assets.ps1`；检查 `.pw.toml` 和 `packwiz-files` diff。 | 已提升为 `.agents/skills/packwiz-assets/SKILL.md`。 |
| 添加或更新 hotai 补丁 | `hotai/`、`docs/dev-knowledge/hotai/`、`.agents/skills/hotai/SKILL.md` | 使用 `/hotai` skill；专题事实写入 `docs/dev-knowledge/hotai/`，不要复制到本索引。 | 运行 `scripts/update-hotai-docs.ps1 -Check` 并按 skill 核对运行时日志。 | 已提升为 `.agents/skills/hotai/SKILL.md`。 |
| 区分测试版和正式版 Packwiz 资产 | 对应的 `mods/`、`resourcepacks/` 或 `shaderpacks/` `.pw.toml` | 将仅允许开发和测试版使用的资产标为顶层 `stable = false`；本地同步和测试版保留，正式版在客户端、服务端、完整性清单及补丁中剔除。具体流程遵循 `/packwiz-assets` skill。 | 运行 `scripts/test-packwiz-stable-filter.py`，并确认正式版产物不含该资产。 | 需要多套发行渠道或按环境动态选择依赖。 |
| 记录已实现内容知识 | `docs/dev-knowledge/content-map.md`，长篇设计写在 `docs/` 专题文档 | 添加短行，包含玩家可见变化、实现概览、主要路径、相关文档和状态。 | 检查链接；涉及路由文件时运行 `scripts/validate-knowledge-base.ps1`。 | 某个内容领域需要独立的重复维护流程。 |
