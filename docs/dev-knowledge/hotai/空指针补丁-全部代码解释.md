# 空指针 HotAI 补丁：全部代码解释

本文解释生成本批六份 `.badiff` 的全部代码，以及运行时/测试时如何套上补丁。位置与根因见 [`空指针补丁-仓库位置与核心解析.md`](空指针补丁-仓库位置与核心解析.md)。

相关路径：

- 补丁产物：`hotai/**/*.badiff`（见解析文档中的六份文件）
- 加载器：`mods/hotai-1.0.jar`
- 目标 JAR：`mods/kubejs-forge-2001.6.5-build.24.jar`、`mods/tacz-1.20.1-1.1.8-hotfix.jar`、`mods/taczaddon.jar`、`mods/quality_food-1.20.1-2.4.3-all.jar`
- 生成器 `NpeHotaiPatches`：从上述 `mods/*.jar` 读取 class，输出到 `hotai/<internal>.badiff`
- 触发测试 `TriggerNpe`：读取 `hotai/*.badiff` 与对应 `mods/*.jar`

---

## 1. HotAI 实际在干什么

游戏启动时 `youyihj.hotai.HotaiTransformationService` 遍历游戏根目录 `hotai/`：

- `.badiff` → `MemoryDiff.deserialize(DefaultSerialization)`，交给 `DiffTransformer`
- `.class` → 完整替换，并可转存为 `.badiff`

`HotaiTransformer.transform(ClassNode)` 的字节路径与生成器必须一致：

```text
ClassNode（ModLauncher 给出的目标类）
  → ClassWriter(0)          // 不重算 frame，得到“基线字节”
  → MemoryDiffs.apply(基线, Diff)
  → ClassReader → 新 ClassNode
  → 交回 Forge；之后运行时会重算 stack map
```

所以生成补丁时也必须：`ClassReader → ClassNode → ClassWriter(0)` 得到 `before`，改 `ClassNode` 后再 `ClassWriter(0)` 得到 `after`，对这两份字节做 `MemoryDiffs.diff`。不能对 JAR 里的原始 class 文件直接 diff，也不能用 `BadiffCli` 的 `BadiffFileDiff`（会 `Not all bytes consumed`）。

五个参数分别是四份模组 JAR 和输出目录。然后对六个 internal name 调 `patch(...)`：

## 3. `patch`：生成单个 `.badiff`

```java
byte[] raw = readClass(jar, internal + ".class");  // 从 JAR 取出 class
ClassNode beforeNode = readNode(raw);
byte[] before = write0(beforeNode);                // HotAI 基线
ClassNode afterNode = readNode(raw);
mutator.apply(afterNode);                          // 插入/替换指令
byte[] after = write0(afterNode);
if (Arrays.equals(before, after)) throw ...;       // 没改到就失败
MemoryDiff diff = MemoryDiffs.diff(before, after);
byte[] applied = MemoryDiffs.apply(before, diff);
if (!Arrays.equals(applied, after)) throw ...;     // 往返必须一致
// 写到 outDir/<internal>.badiff
diff.serialize(DefaultSerialization.newInstance(), os);
```

辅助函数：

- `readClass`：`JarFile` 读指定 entry 的全部字节。
- `readNode`：`new ClassReader(raw).accept(new ClassNode(), 0)`。flag `0` 保留原 stack map。
- `write0`：`new ClassWriter(0)`。flag `0` 表示不 `COMPUTE_FRAMES`，与 HotAI 一致。
- `method(cn, name, desc)`：按方法名 + JVM 描述符精确查找，找不到抛错。

## 4. `patchGeneratedData`：整方法替换 `GeneratedData.get`

原方法：

```java
public InputStream get() {
    var in = new ByteArrayInputStream(data.get());
    if (alwaysForget) data.forget();
    return in;
}
```

生成器丢掉原指令列表，写成：

```java
byte[] tmp = (byte[]) this.data.get();   // 栈上 DUP
if (tmp == null) tmp = new byte[0];      // IFNONNULL / POP / ICONST_0 / NEWARRAY T_BYTE
this 的局部 2 = tmp;
InputStream in = new ByteArrayInputStream(tmp);  // 局部 1
if (this.alwaysForget) this.data.forget();
return in;
```

指令顺序：

1. `ALOAD 0` + `GETFIELD data` + `INVOKEVIRTUAL Lazy.get` + `CHECKCAST [B`
2. `DUP`；`IFNONNULL nonNull`；`POP`；`ICONST_0`；`NEWARRAY T_BYTE`
3. 标签 `nonNull`：`ASTORE 2`（空数组或原数组）
4. `NEW ByteArrayInputStream` + `DUP` + `ALOAD 2` + `<init>([B)V` + `ASTORE 1`
5. `GETFIELD alwaysForget`；`IFEQ skipForget`；再 `GETFIELD data` + `forget()`
6. `ALOAD 1` + `ARETURN`

`tryCatchBlocks` 清空（原方法无异常表，避免残留）。`maxLocals ≥ 3`，`maxStack ≥ 3`。

`PACK_ICON` 的 `alwaysForget=true` 仍会 `forget()`，只是构造流时不再把 null 传给 JDK。

## 5. `patchCommonAssetsManager`：整方法替换 `getNetworkCache`

原方法：

```java
ImmutableMap.Builder<...> builder = ImmutableMap.builder();
for (INetworkCacheReloadListener listener : listeners) {
    builder.put(listener.getType(), listener.getNetworkCache());
}
return builder.build();
```

新方法把 cache 先存局部 4，null 则跳过 `put`：

```java
Builder builder = ImmutableMap.builder();          // 局部 1
Iterator it = this.listeners.iterator();           // 局部 2
loop:
if (!it.hasNext()) goto end;
INetworkCacheReloadListener listener = (INetworkCacheReloadListener) it.next(); // 局部 3
Map cache = listener.getNetworkCache();            // 局部 4
if (cache == null) goto skip;
builder.put(listener.getType(), cache); POP
skip:
goto loop
end:
return builder.build();
```

关键指令：`ALOAD 4` + `IFNULL skip`，然后才 `Builder.put`。Guava 的 `put` 不允许 null value，这就是原崩溃点。

`maxLocals ≥ 5`，`maxStack ≥ 3`。

## 6. `patchCommonDataManager`：整方法替换字段 getter

原方法就是 `return this.networkCache;`（字段默认 null）。

新方法：

```java
Map cache = this.networkCache;
if (cache != null) return cache;
return Map.of();
```

指令：

1. `ALOAD 0` + `GETFIELD networkCache`
2. `DUP` + `IFNONNULL nonNull`
3. `POP` + `INVOKESTATIC Map.of()Ljava/util/Map;`
4. 标签 `nonNull`：`ARETURN`

`DUP` 是为了非空时栈上仍留着 map 可供返回；空则扔掉再压 `Map.of()`。

## 7. `patchBackpackCompat`：在原方法头插入守卫

不整段替换，避免碰精致背包其余逻辑。

### 7.1 `addBackpackItems(ArrayList, IBackpackWrapper)`

这是 **static** 方法：局部 0 = list，局部 1 = wrapper。原代码：

```java
if (wrapper == Noop.INSTANCE) return;
InventoryHandler h = wrapper.getInventoryHandler(); // wrapper==null 时 NPE
```

`null != INSTANCE` 为 true，所以 Noop 判断拦不住 null。

插入到方法最前面：

```java
if (list == null || wrapper == null) return;
```

对应：

```
ALOAD 0
IFNULL ret
ALOAD 1
IFNULL ret
GOTO cont
ret: RETURN
cont:  // 原指令接着执行
```

文件里有一段写了又不用的 `head` / `retLabel`（死代码），真正生效的是后面的 `guard`。`retLabel()` 只 `new LabelNode()`，从未插入指令列表，对输出无影响。

### 7.2 `getItemsFromBackpackBLock(BlockPos, Player)`

static：局部 0 = pos，1 = player，2 = 新建的 `ArrayList`，3 = `BackpackContext.Block`，4 = wrapper。

原代码在 `astore 4` 之后立刻 `addBackpackItems(list, wrapper)`。

生成器扫描第一条 `ASTORE 4`，在其后插入：

```
ALOAD 4
IFNONNULL present
ALOAD 2
ARETURN          // wrapper 为 null 时返回已有空列表
present:
```

这样方块上没有背包时返回 `[]`，不再把 null wrapper 传下去。

## 8. `patchLevelData`：三处插入

### 8.1 实例 `set(BlockPos, Quality)`

局部 0 = this，1 = pos，2 = quality。原代码只判断 `quality == Quality.NONE`。

插在方法头：

```
ALOAD 2
IFNONNULL notNull
ALOAD 0
ALOAD 1
INVOKEVIRTUAL remove(BlockPos)V
RETURN
notNull:
```

等价：`if (quality == null) { remove(pos); return; }`。null 不再 `put` 进 `HashMap`。

### 8.2 `serializeNBT`

循环里栈在 `ordinal()` 之前是：`CompoundTag`、`String key`、`Quality`（可能为 null）。

找到第一次 `Quality.ordinal`，再找到循环的 `GOTO`，在 `ordinal` 前插入：

```
DUP                    // 复制 Quality
IFNONNULL ok
POP                    // 扔掉 Quality
POP                    // 扔掉 String
POP                    // 扔掉 CompoundTag（本轮 putInt 的 receiver）
GOTO 循环头
ok:
// 原 ordinal + putInt
```

三个 `POP` 把本轮 `putInt` 的参数拆干净，再跳回 `hasNext`。已经写进 map 的脏 null 不会在存档时炸。

`maxStack ≥ 4`（DUP 多压一层）。

### 8.3 静态 `get(LevelAccessor, BlockPos, boolean)`

`lastRemoved.getSecond()` 之后是 `CHECKCAST Quality` + `ASTORE 4`。null 的 checkcast 合法，但后面调用方对结果 `ordinal()` 会炸。

在该 `ASTORE 4` 前（且前一条必须是 `CHECKCAST Quality`）插入：

```
DUP
IFNONNULL present
POP
GETSTATIC Quality.NONE
present:
ASTORE 4
```

空的 lastRemoved 品质变成 `NONE`。找不到这种 `astore` 就跳过（保护描述符变化）。

## 9. `patchBlockData`：两处插入

### 9.1 `addQualityEntry(Quality, double)`

局部 1 = quality。方法头：

```
ALOAD 1
IFNONNULL cont
RETURN
cont:
```

null 不入队，不会出现 `CookingEntry(null, bonus)`。

### 9.2 `serializeNBT`

循环体在调用 `entry.quality()` 之后栈是：`entryTag`、`"quality"`、`Quality`。补丁插在 `quality()` **之后**、`ordinal()` 之前：

同样 `DUP` + `IFNULL` + 三个 `POP` + `GOTO` 循环。null 条目整条丢掉（连 bonus 的 `putDouble` 也不写），避免脏队列把存档打崩。

循环 `GOTO` 从方法**末尾往前**找，因为前面可能还有别的跳转。

## 10. `TriggerNpe.java`：怎么证明补丁有效

不启动 329 个模组的完整服务端，而是：

1. 从官方包 JAR 取出 class，按 HotAI 做成 `before`
2. 反序列化 `hotai/*.badiff`，`MemoryDiffs.apply`
3. `ClassWriter.COMPUTE_FRAMES` 重算 stack map（模拟 Forge 加载后的类）
4. 自定义 `ClassLoader` 分别加载「未打补丁 / 已打补丁」两份字节
5. 用桩类代替 Minecraft（`BlockPos.m_121878_`、`CompoundTag.m_128405_` 等 SRG 名）
6. 调用崩溃路径：未打补丁期望 NPE，打了期望不崩

六个补丁对应的触发点：

| 调用 | 未打补丁 | 已打补丁 |
|---|---|---|
| `LevelData.set(pos, null)` 再 `serializeNBT` | `HashMap.get` 为 null 后 `ordinal()` | 当成 remove，正常序列化 |
| map 里已经 `put(null)` 再序列化 | 同上 | 跳过空条目 |
| `get(level, pos, true)` 且 `lastRemoved.second == null` 再 `ordinal()` | 返回 null | 返回 `NONE` |
| `BlockData.addQualityEntry(null)` 再序列化 | `CookingEntry.quality()` 为 null | 不入队 |
| `GeneratedData.get()` 且 `Lazy.of(() -> null)` | `ByteArrayInputStream(null)` | 空字节流 |
| `CommonDataManager.getNetworkCache()` 字段仍 null | 返回 null | `Map.of()` |
| `CommonAssetsManager.getNetworkCache()` 监听器 cache 为 null | Guava `GUN=null` | 跳过，得到 `{}` |
| `addBackpackItems(list, null)` | `getInventoryHandler()` NPE | 直接 return |
| `getItemsFromBackpackBLock` 且 wrapper 为 null | 转到上一行崩 | 返回 `[]` |

结果：18/18。TACZ 两个方法从完整 class 抽到 `HarnessCAM` / `HarnessCDM`，背包两个方法抽到 `HarnessBP`，避免加载整个 TACZ/背包类的 `<clinit>`。

`Isolated` 是子优先 ClassLoader：`java.*` / Guava / Gson 走系统；Quality 用生成的枚举桩（避免 `Component.translatable`）；其余 MC 类型按需生成空类。`RandomSource` 必须是接口且静态方法名为 `m_216327_`（BlockData 的 `<clinit>`）。

