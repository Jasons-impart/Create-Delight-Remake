# Quality Food 存储配方 Hotai 补丁逐指令说明

本文说明 `release-v050x` 使用的五个品质继承 `.badiff`。补丁针对 Minecraft 1.20.1、Forge 47.4.16、Quality Food 2.4.3、Create 6.0.8、Vintage Improvements 0.3.7.8、Quark 4.0-462 生成；`.badiff` 文件是 Hotai `MemoryDiff` 序列化结果，不是可直接替换的完整 class。

## 共同调用约定

以下名称使用 1.20.1 Forge 映射：

| 名称 | 实际含义 |
|---|---|
| `m_41777_()` | `ItemStack.copy()` |
| `m_5874_(Container, RegistryAccess)` | `CraftingRecipe.assemble(...)` |
| `m_9598_()` | `Level.registryAccess()` |
| `m_58904_()` | Create Basin 的 `getLevel()` |
| `handleConversion(output, container, recipe, level)` | Quality Food 品质继承入口；它按输入品质、存储配方缓存和 `retain_quality` 配置决定是否写入输出 |

每个目标路径由 `.badiff` 相对 `hotai/` 的路径直接推导。例如 `hotai/org/violetmoon/quark/.../CrafterBlockEntity.badiff` 的目标 internal name 是 `org/violetmoon/quark/.../CrafterBlockEntity`。补丁不修改任何上游 JAR。

## 1. CDC 工作盆 BasinRecipeMixin

文件：`io/github/jasonsimpart/createdelightcore/mixin/create/BasinRecipeMixin.badiff`。

目标模组：`Create-Delight-Core-1.20.1-dev.jar`。目标方法是 CDC Mixin 的 `quality_food$applyQuality`，原方法的三个输入为输出列表、相关输入数量引用和权重引用；补丁从原始方法参数局部变量 `3`、`4` 捕获 `Recipe` 和 `BasinBlockEntity`。

### 描述符和参数元数据

1. 在返回类型之前追加 `Lnet/minecraft/world/item/crafting/Recipe;Lcom/simibubi/create/content/processing/basin/BasinBlockEntity;`，因此方法多接收配方和工作盆；工作盆类来自 Create，而不是 CDC 包。
2. 原前三个参数注解保留。
3. 新增的两个参数各写入 `@Local(argsOnly = true)`，让 MixinExtras 把它们作为原始参数捕获。
4. `maxLocals` 设为 `5`，清除旧 `FrameNode`，由 Hotai/Forge 在转换后重新计算栈帧。

### 插入的指令顺序

```text
ALOAD 3
ALOAD 4
INVOKEVIRTUAL BasinBlockEntity.m_58904_() : Level
INVOKESTATIC ServerConfig.isNoQualityRecipe(Recipe, Level) : boolean
IFNE skip

ALOAD 3
ALOAD 4
INVOKEVIRTUAL BasinBlockEntity.m_58904_() : Level
INVOKEVIRTUAL Level.m_9598_() : RegistryAccess
INVOKESTATIC ServerConfig.isRetainQualityRecipe(Recipe, RegistryAccess) : boolean
IFEQ proceed

skip:
ALOAD 0
ARETURN

proceed:
```

逐行栈效果如下：

| 行 | 指令 | 栈效果与目的 |
|---:|---|---|
| 1 | `ALOAD 3` | 压入当前配方。 |
| 2 | `ALOAD 4` | 压入 Basin。 |
| 3 | `Basin.m_58904_` | 消耗 Basin，得到当前 Level。 |
| 4 | `isNoQualityRecipe` | 查询“无品质”配置。 |
| 5 | `IFNE skip` | 配方被标为无品质时跳到返回。 |
| 6 | `ALOAD 3` | 再次压入配方。 |
| 7 | `ALOAD 4` | 再次压入工作盆。 |
| 8 | `Basin.m_58904_` | 用工作盆替换栈顶，得到 Level。 |
| 9 | `Level.m_9598_` | 得到 RegistryAccess。 |
| 10 | `isRetainQualityRecipe` | 查询保留品质配置。 |
| 11 | `IFEQ proceed` | 未配置保留时继续原始随机品质逻辑。 |
| 12 | `ALOAD 0` | 压入原输出列表。 |
| 13 | `ARETURN` | 保留配方直接返回原输出，不重新抽取品质。 |

这个保护只改变“无品质”和“保留品质”两类配方；普通加工仍进入原有的 Quality Food 逻辑。

## 2. Quality Food 工作盆 BasinRecipeMixin

文件：`de/cadentem/quality_food/mixin/create/BasinRecipeMixin.badiff`。

目标模组：`quality_food-1.20.1-2.4.3-all.jar`。目标方法是 `quality_food$applyQualityMultiple`。

补丁扫描该方法的所有调用，只匹配：

```text
owner = net/minecraft/world/item/ItemStack
name  = m_41777_
```

本版本恰好找到一个调用，删除这一条 `ItemStack.copy()` 指令，其他指令、分支和局部变量不变。这样存储配方的输出对象不会先被复制成没有后续品质写入的临时对象；CDC 的方法保护和 Quality Food 原有的多物品最低品质计算仍保留。

构建器在匹配数量不是 `1` 时终止，避免针对 Quality Food 版本变化静默生成错误补丁。

## 3. Create 动力合成器 RecipeGridHandler

文件：`com/simibubi/create/content/kinetics/crafter/RecipeGridHandler.badiff`。

目标模组：`create-1.20.1-6.0.8.jar`。目标类的两个 lambda 是动力合成器的普通合成和备用合成回调。

### `lambda$tryToApplyRecipe$1`

1. 在原配方参数前加入 `Level` 参数，描述符由 `(..., CraftingRecipe)ItemStack` 变为 `(..., Level, CraftingRecipe)ItemStack`。
2. 清空原指令、异常表和局部变量表。
3. 写入以下完整逻辑：

```text
ALOAD 3
ALOAD 0
ALOAD 1
INVOKEINTERFACE CraftingRecipe.m_5874_(Container, RegistryAccess) : ItemStack
INVOKEVIRTUAL ItemStack.m_41777_() : ItemStack
ASTORE 4
ALOAD 4
ALOAD 0
ALOAD 3
ALOAD 2
INVOKESTATIC QualityUtils.handleConversion(ItemStack, Container, Recipe, Level)
ALOAD 4
ARETURN
```

局部变量映射为 `0=CraftingContainer`、`1=RegistryAccess`、`2=Level`、`3=CraftingRecipe`、`4=ItemStack`。`ALOAD 3` 加载配方，不是 Level；`ALOAD 0/1` 分别加载容器和注册表访问对象。下表逐条对应上方的 13 条指令。

| 指令行 | 指令 | 栈操作与目的 |
|---:|---|---|
| 1 | `ALOAD 3` | 加载配方，作为接口调用接收者。 |
| 2 | `ALOAD 0` | 加载输入合成容器。 |
| 3 | `ALOAD 1` | 加载 RegistryAccess。 |
| 4 | `INVOKEINTERFACE m_5874_` | 消耗配方、容器和 RegistryAccess，压入组装产物。 |
| 5 | `INVOKEVIRTUAL m_41777_` | 复制产物，避免写入配方共享的结果模板。 |
| 6 | `ASTORE 4` | 将复制产物存入局部变量 4。 |
| 7 | `ALOAD 4` | 加载待写品质的复制产物。 |
| 8 | `ALOAD 0` | 加载输入容器。 |
| 9 | `ALOAD 3` | 加载实际配方。 |
| 10 | `ALOAD 2` | 加载捕获的 Level。 |
| 11 | `INVOKESTATIC handleConversion` | 消耗四个参数，在产物上继承品质；返回 void。 |
| 12 | `ALOAD 4` | 加载已经写入品质的产物。 |
| 13 | `ARETURN` | 返回该产物。 |

### `lambda$tryToApplyRecipe$2`

第二个 lambda 使用同样的五个局部变量和完全相同的指令顺序，区别仅在于其配方参数类型是通用 `Recipe`，因此 `m_5874_` 的接口所有者按通用配方描述符写入。两条回调都必须修复，否则动力合成器在备用路径仍会丢品质。

### 两个 invokedynamic 调用点

补丁随后扫描 `tryToApplyRecipe` 的两个 `InvokeDynamicInsnNode`：

1. 当 bootstrap 参数中的 `Handle` 名称是 `lambda$tryToApplyRecipe$1` 或 `$2` 时，替换为带 `Level` 参数的新方法描述符。
2. 把函数描述符的返回前部分从 `)Ljava/util/function/Function;` 改为 `Lnet/minecraft/world/level/Level;)Ljava/util/function/Function;`。
3. 在每个 invokedynamic 前插入 `ALOAD 0`，把当前 Level 捕获到 lambda。
4. 必须恰好捕获两个调用点，否则构建失败。

## 4. Vintage Improvements 振动台 VibratingTableBlockEntity

文件：`com/negodya1/vintageimprovements/content/kinetics/vibration/VibratingTableBlockEntity.badiff`。

目标模组：`vintageimprovements-1.20.1-0.3.7.8.jar`。目标方法是 `process`，原方法局部变量 `5` 是解包前物品，局部变量 `6` 是解包结果。

### `process` 中的两处插入

在第一次对局部变量 `5` 执行 `ASTORE` 后插入：

```text
ALOAD 5
INVOKEVIRTUAL ItemStack.m_41777_() : ItemStack
ASTORE snapshot
```

`snapshot` 使用原方法 `maxLocals` 之后的第一个局部变量，保存未被后续数量扣减修改的品质来源物品。

在第一次对局部变量 `6` 执行 `ASTORE` 后插入：

```text
ALOAD 6
ALOAD snapshot
ALOAD 4
INVOKEVIRTUAL Optional.get() : Object
CHECKCAST Recipe
ALOAD 0
GETFIELD VibratingTableBlockEntity.f_58857_ : Level
INVOKESTATIC VibratingTableBlockEntity.hotai$retainUnpackingQuality(
    ItemStack, ItemStack, Recipe, Level) : ItemStack
ASTORE 6
```

这里保留原解包结果对象作为第一个参数，传入快照作为第二个参数；局部变量 `4` 的 Optional 取出当前配方；`ALOAD 0` 后读取方块实体的 Level；helper 返回带品质的结果并覆盖原局部变量 `6`。方法帧被清除，`maxLocals` 增加一个槽位。

### 新增 helper 的逐指令逻辑

新增私有静态方法：

```text
hotai$retainUnpackingQuality(ItemStack output, ItemStack source,
                            Recipe recipe, Level level) : ItemStack
```

```text
ALOAD 1
ICONST_1
INVOKEVIRTUAL ItemStack.m_41764_(int) : void

ALOAD 0
NEW SimpleContainer
DUP
ICONST_1
ANEWARRAY ItemStack
DUP
ICONST_0
ALOAD 1
AASTORE
INVOKESPECIAL SimpleContainer.<init>(ItemStack[]) : void
ALOAD 2
ALOAD 3
INVOKESTATIC QualityUtils.handleConversion(ItemStack, Container, Recipe, Level)
ALOAD 0
ARETURN
```

第一至三行把来源快照数量设为 `1`，使解包缓存按一份来源物品计算；接下来创建容量为 `1` 的 `SimpleContainer`，把来源快照放入槽 `0`；最后把输出、这个临时容器、配方和 Level 传入 Quality Food，返回原输出对象。原始解包消耗和数量逻辑不被 helper 改写。

## 5. Quark 合成器 CrafterBlockEntity

文件：`org/violetmoon/quark/content/automation/block/be/CrafterBlockEntity.badiff`。

目标模组：`Quark-4.0-462.jar`。目标方法是公开静态 `getResult(Level, CraftingContainer)`，Quark 原方法只调用 `CraftingRecipe.m_5874_` 后返回产物，因此绕过 Quality Food。

在 `CraftingRecipe.m_5874_` 返回值之后插入：

```text
INVOKEVIRTUAL ItemStack.m_41777_() : ItemStack
DUP
ALOAD 1
ALOAD 3
ALOAD 0
INVOKESTATIC QualityUtils.handleConversion(ItemStack, Container, Recipe, Level)
```

精确栈变化为：原版产物先复制；`DUP` 将同一个复制产物的引用压入两次，并不创建第二个对象；`ALOAD 1` 压入 Quark 的九格 `CraftingContainer`；`ALOAD 3` 压入 `RecipeManager` 找到的 `CraftingRecipe`；`ALOAD 0` 压入 Level；`handleConversion` 消耗输出引用、容器、配方和 Level，并在该复制对象上写入最低输入品质；栈上剩余的同一对象引用继续执行 Quark 原有的 feature flag 检查和 `ARETURN`。

因此同一入口同时覆盖 Quark 合成器的压块和解包：九个相同品质的食物压成块保持该品质，带品质的块解包成九个食物保持该品质，混合输入按 Quality Food 的最低品质规则处理。

## 生成与验证

`.badiff` 是二进制，没有文本行号；本文的“每行”指补丁新增、删除或替换的每条字节码指令。标签不执行指令；元数据改动另外记录，未改的第三方方法体不重复展开。

### 振动台每条指令补充说明

`process()V` 是实例方法：`0=this`、`4=Optional<Recipe>`、`5=来源`、`6=解包产物`。新增 `snapshot` 的索引取原方法 `maxLocals`，不是固定猜测一个槽位。

| 插入位置 | 指令行 | 指令 | 操作 |
|---|---:|---|---|
| 首次 `ASTORE 5` 后 | 1 | `ALOAD 5` | 加载来源。 |
| 同上 | 2 | `INVOKEVIRTUAL copy` | 复制来源，隔离后续消耗。 |
| 同上 | 3 | `ASTORE snapshot` | 保存复制来源。 |
| 首次 `ASTORE 6` 后 | 1 | `ALOAD 6` | 加载现有解包结果。 |
| 同上 | 2 | `ALOAD snapshot` | 加载来源快照。 |
| 同上 | 3 | `ALOAD 4` | 加载匹配配方的 Optional。 |
| 同上 | 4 | `INVOKEVIRTUAL Optional.get` | 取出配方对象。 |
| 同上 | 5 | `CHECKCAST Recipe` | 将栈顶对象类型收窄为 Recipe。 |
| 同上 | 6 | `ALOAD 0` | 加载方块实体。 |
| 同上 | 7 | `GETFIELD f_58857_` | 读取其 Level。 |
| 同上 | 8 | `INVOKESTATIC hotai$retainUnpackingQuality` | 调用四参数 helper，返回原结果对象。 |
| 同上 | 9 | `ASTORE 6` | 覆盖产物局部变量。 |

新增 helper 是 `private static`，`0=output`、`1=source`、`2=recipe`、`3=level`，局部变量数为 4；下表对应前文 helper 的 18 条实际指令，空行不计数。

| 指令行 | 指令 | 操作 |
|---:|---|---|
| 1 | `ALOAD 1` | 加载来源快照。 |
| 2 | `ICONST_1` | 压入来源数量 1。 |
| 3 | `INVOKEVIRTUAL m_41764_(I)V` | 对快照执行 setCount(1)，不改原库存。 |
| 4 | `ALOAD 0` | 加载输出，暂留在栈底。 |
| 5 | `NEW SimpleContainer` | 压入未初始化容器引用。 |
| 6 | `DUP` | 复制容器引用，供构造器消耗其中一个。 |
| 7 | `ICONST_1` | 压入数组长度 1。 |
| 8 | `ANEWARRAY ItemStack` | 建立长度 1 的来源数组。 |
| 9 | `DUP` | 复制数组引用，保留一份传构造器。 |
| 10 | `ICONST_0` | 压入数组索引 0。 |
| 11 | `ALOAD 1` | 加载来源快照。 |
| 12 | `AASTORE` | 写入数组第 0 项，消耗数组引用、索引、来源。 |
| 13 | `INVOKESPECIAL SimpleContainer.<init>` | 用来源数组初始化容器；栈上留下输出和已初始化容器。 |
| 14 | `ALOAD 2` | 加载配方。 |
| 15 | `ALOAD 3` | 加载 Level。 |
| 16 | `INVOKESTATIC handleConversion` | 消耗输出、容器、配方和 Level，写入品质。 |
| 17 | `ALOAD 0` | 再加载原输出对象。 |
| 18 | `ARETURN` | 返回带品质的原输出。 |

### Quark 每条指令补充说明

| 指令行 | 指令 | 操作 |
|---:|---|---|
| 1 | `INVOKEVIRTUAL copy` | 把栈顶组装结果复制为独立产物。 |

### 白盒记录与验证范围

完整断言输出见 [品质存储修复-白盒测试记录.md](品质存储修复-白盒测试记录.md)。工作盆、动力合成器和振动台白盒使用隔离类加载器加载补丁后的目标类；Quark 另验证重启后的 Hotai 运行类。上述白盒用临时物品和容器执行真实回调，不等同于所有机器都经过游戏内完整生产循环；用户已确认本次 Hotai 功能正常。

- 五个文件均由 Hotai 1.0 的 `MemoryDiffs.diff` 和 `DefaultSerialization` 生成，禁止使用其他 diff 序列化格式。
- 生成后对每个 `.badiff` 反序列化并重放，结果 class 与目标字节逐字节一致；ASM `BasicVerifier` 通过。
- 白盒覆盖 NONE、IRON、GOLD、DIAMOND、IRON+GOLD、IRON+NONE，检查输入和配方模板没有被修改。
- 重启指定测试服后，日志出现 `Patched class: org/violetmoon/quark/content/automation/block/be/CrafterBlockEntity`；运行时压块、解包和混合品质断言全部通过。
- Quark 原始 `Quark-4.0-462.jar` 未写入；安装内容仅为 `server/hotai/` 下的 `.badiff`。

## 维护边界

这些补丁与上述五个目标 JAR 的方法描述符和局部变量布局绑定。升级 Quality Food、Create、Vintage Improvements 或 Quark 后，必须重新扫描目标 class、重新生成 `MemoryDiff`、运行本文件列出的白盒矩阵，并检查启动日志；上游若加入原生品质继承，应优先移除重复补丁。
