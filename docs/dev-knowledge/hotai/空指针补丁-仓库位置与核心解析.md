## 加载路径

HotAI 对每个 `.badiff` 做：

1. ModLauncher 给出目标 `ClassNode`
2. `ClassWriter(0)` 写成基线字节（与生成补丁时相同）
3. `MemoryDiffs.apply` 套上 `DefaultSerialization` 读出的 `MemoryDiff`
4. 再读回 `ClassNode` 交给 Forge；运行时会重算 stack map

因此补丁与目标 JAR 版本强绑定。升级 Quality Food / KubeJS / TACZ / taczaddon 后必须对同一 class 重新生成。

## 核心代码解析

三族根因都是「把 `null` 当成合法业务值，随后对它调实例方法或塞进拒绝空值的容器」。`quality == Quality.NONE` 拦不住 `null`，因为 `null == NONE` 为 false。

### 1. Quality Food：空品质进 HashMap，序列化 `ordinal()` 崩溃

`LevelData.set` 原逻辑：

```java
public void set(final BlockPos position, final Quality quality) {
    if (quality == Quality.NONE) {
        remove(position);
        return;
    }
    qualities.put(position.asLong(), quality); // quality 为 null 时仍 put
}
```

`serializeNBT` 无条件：

```java
for (Long key : qualities.keySet()) {
    tag.putInt(String.valueOf(key), qualities.get(key).ordinal());
}
```

`HashMap` 允许 null value。收割机等路径会把 `get(level, pos, true)` 取到的空品质写回；`lastRemoved.getSecond()` 在方块已移除后也可以是 null。存档或卸载世界时走到 `ordinal()` 即 NPE。

`BlockData` 同族：`addQualityEntry(null, bonus)` 会入队 `CookingEntry(null, bonus)`，序列化时 `entry.quality().ordinal()` 崩溃。

第一版补丁把 `null` 当成清除：`LevelData.set` 调用 `remove()`，`BlockData.addQualityEntry` 直接返回。`remove()` 会真删品质，并覆盖单槽 `lastRemoved`，多个品质物品合并时的转移链被打断；`BlockData` 的早退则会丢掉品质信息。离线用例里表现为 `retainQuality` 未保留、`retainChain` 未接上。不打补丁时转移链本身是通的。

当前 `.badiff` 的语义：

```java
// LevelData.set：空值不写入，也不删除已有品质
if (quality == null) {
    return;
}

// LevelData.serializeNBT：脏数据仍跳过
Quality q = qualities.get(key);
if (q == null) continue;
tag.putInt(String.valueOf(key), q.ordinal());

// LevelData.get(level, pos, queryLastRemoved)
Quality fromLast = data.lastRemoved.getSecond();
result = fromLast != null ? fromLast : Quality.NONE;

// BlockData.addQualityEntry：空值落成 NONE，条目保留
if (quality == null) quality = Quality.NONE;

// BlockData.serializeNBT
if (entry.quality() == null) continue;
```

实例 `get(BlockPos)` 本身已把 map 里的 null 收成 `NONE`，真正炸的是序列化和「把 lastRemoved 空值当品质用」的调用方。

### 2. KubeJS：`Lazy.get()` 为 null 时构造 `ByteArrayInputStream`

```java
public InputStream get() {
    var in = new ByteArrayInputStream(data.get()); // data.get() 可为 null
    if (alwaysForget) {
        data.forget();
    }
    return in;
}
```

`ByteArrayInputStream(byte[])` 读 `buf.length`，`buf == null` 即 NPE。工厂返回 null、或 `forget()` 后再读，都会打到这条路径。数据包重载、KubeJS 内部 `__internal.reload` 都走 `GeneratedData.get()`。

补丁后：

```java
byte[] bytes = (byte[]) data.get();
if (bytes == null) bytes = new byte[0];
InputStream in = new ByteArrayInputStream(bytes);
if (alwaysForget) data.forget();
return in;
```

空内容变成合法空流，不再把 NPE 抛进资源重载。

### 3. TACZ：未 `apply()` 的 `networkCache` 进入 `ImmutableMap.put`

```java
// CommonDataManager
protected Map<ResourceLocation, String> networkCache; // 默认 null

public Map<ResourceLocation, String> getNetworkCache() {
    return this.networkCache;
}

// CommonAssetsManager
public Map<DataType, Map<ResourceLocation, String>> getNetworkCache() {
    ImmutableMap.Builder<...> builder = ImmutableMap.builder();
    for (INetworkCacheReloadListener listener : listeners) {
        builder.put(listener.getType(), listener.getNetworkCache()); // value 为 null 时 Guava 抛 NPE
    }
    return builder.build();
}
```

`networkCache` 只在 `apply()` 里赋成 `ImmutableMap`。资源同步、进服、数据包重载若发生在某类监听器尚未 apply 时，`put(GUN, null)` 会变成 `null value in entry`。

补丁后两层一起挡：

```java
// CommonDataManager
public Map<ResourceLocation, String> getNetworkCache() {
    Map<ResourceLocation, String> cache = this.networkCache;
    return cache != null ? cache : Map.of();
}

// CommonAssetsManager
Map<?, ?> cache = listener.getNetworkCache();
if (cache != null) {
    builder.put(listener.getType(), cache);
}
```

未就绪的类型从同步包里缺席，而不是把 null 交给 Guava。

### 4. TACZ-addon：精致背包 wrapper 为 null 仍 `invokeinterface`

`addBackpackItems` 先把 wrapper 和 `IBackpackWrapper.Noop.INSTANCE` 做引用比较。`null != INSTANCE` 为 true，于是落到 `wrapper.getInventoryHandler()`，对 null 调接口即 NPE。

`getItemsFromBackpackBLock` 在 `BackpackContext.Block.getBackpackWrapper(player)` 返回 null 后，立刻把这个 null 交给 `addBackpackItems`。

补丁后：

```java
private static void addBackpackItems(ArrayList<ItemStack> list, IBackpackWrapper wrapper) {
    if (list == null || wrapper == null) return;
    // 原 Noop.INSTANCE 判断与取物品循环不变
}

public static ArrayList<ItemStack> getItemsFromBackpackBLock(BlockPos pos, Player player) {
    ArrayList<ItemStack> list = new ArrayList<>();
    IBackpackWrapper wrapper = new BackpackContext.Block(pos).getBackpackWrapper(player);
    if (wrapper == null) return list;
    addBackpackItems(list, wrapper);
    return list;
}
```

没有背包方块或 capability 未就绪时返回空列表，不再崩。

## 离线触发点结果

对 `hotai/` 下这六份 `.badiff` 按 HotAI 相同基线套补丁后，直接调用崩溃路径：未打补丁会 NPE（或返回会喂给 `ImmutableMap.put` 的 null），打补丁后全部通过，18/18。游戏内收割存档、`/kubejs reload`、TACZ 进服同步、打开精致背包仍可作为运行时回归。
